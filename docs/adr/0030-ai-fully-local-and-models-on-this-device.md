# ADR 0030: "Fully local" is one switch with one promise, held where every request passes — and a model on this device is what its user says it is

Status: Accepted

Date: 2026-10-09

## Context

[ADR 0021](0021-ai-local-inference-and-platform-models.md) promised that sensitive areas can stay fully local. The plan names three modes — Cloud, Hybrid, Fully local ("local embeddings and generation, zero egress") — and the first mockup drew them as three segments in the settings. What exists is every part of that and no promise: a server on the user's own computer or the system's own model can answer, a package on the device computes search by meaning, the profile "Local" writes the gists and reads e-mails. Where something goes is decided choice by choice — by the provider of a profile, the vault's switch for the internet, a note's rule.

Three facts shape everything.

**Three positions would be two states and one promise.** Cloud and Hybrid do not differ by a choice. A user who chose a provider and loaded a package for search *is* hybrid; a third control could only repeat that or contradict it. Only "Fully local" says something the other settings do not: that nothing leaves.

**A promise kept at many switches is kept until one is forgotten.** A request to a model starts in a dozen places — a conversation, a skill, a regression run, a review, a column being filled, a sentence that becomes a filter, a voice note, a picture, a comment thread, a gist, the reader of an e-mail, the reader of a web page, a connection test, the embeddings of search by meaning through a provider. And a model is not the only way out: a page fetched, a foreign MCP server, an external agent, the MCP server other AI apps read the vault through, the list of titles the system's assistant is given.

**A server on the user's computer says nothing about its models.** Not their window, not whether they call tools. A request longer than the window is cut without a word — the model then answers from a conversation whose beginning it never read, and nothing says so. A model that cannot call tools is handed twenty of them and a prompt that explains them.

## Decision

1. **One switch, per device, off until chosen.** While "Fully local" is on, only models on this device answer, and nothing the assistant handles goes to a provider, to the internet or to another program. It holds on this device in every vault, is stored with the device's AI settings (`localOnly`) and is never synced.

2. **"On this device" is a kind of provider, not a claim.** A server under this computer's own address — `localhost`, `127.0.0.1`, `::1`, the names plain http is accepted for — or the system's own model on the device (`runsOnDevice`). Not Apple's Private Cloud Compute, which is a server with Apple's assurances. Not a gateway. Not a server in the home network: an address outside this device is not this device, however near it stands.

3. **Held at the one egress.** The session wraps the shell's egress once (`localOnlyEgress`) and sends everything through the wrapper: while the switch is on, a request whose endpoint is not on this device is answered with the failure `local_only` and handed to nobody. A conversation, a door, a review, a transcription, a connection test and the egress search by meaning uses all pass it, so none of them has to remember the rule. `aiSession.ts` names the host's egress exactly once — where it puts the switch in front of it — and a test keeps it at once. Until the settings are read the wrapper refuses as well: what the switch says is not known yet. Keys and servers can still be managed; managing sends nothing.

4. **What has a way out of its own rests at its own door.** The internet: not offered, not chosen, and a conversation that was begun with it reads no page from then on. Foreign MCP servers: none is offered, asked or called — a program on this computer included, because what it passes on nobody here can see —, and their connections and programs end. External agents: none is started. The MCP server for AI apps on this computer does not listen. The list of note titles for the system's assistant is not kept. Each stays set up as it was; it rests.

5. **Switching on ends what is under way.** The wrapper knows the requests in flight and cancels those that go to anyone but this device, like the user's own STOP; a request to the model on this device goes on. A page or a call that waits for an answer gets a no, a send overview is cancelled, a choice of model or of the internet for the next conversation is taken back, an agent's session ends.

6. **The switch chooses nothing.** It picks no model and changes no profile. A new conversation is answered by one of the user's own choices: the default profile where its model runs on this device, else the profile "Local", else the first chat profile whose model does. Where none does, the ordinary choice stays named and is refused — so the answer says which provider is not this device instead of that nothing was chosen. A conversation that ran with a provider's model does not go on: no conversation changes its model silently; the way on is a new conversation. Switched off, everything is as it was set up.

7. **A door says so before it reads, asks or builds.** The ways beside the composer — transcribing, a picture, a comment thread, a selection, a column, a filter, a review — check the model first and report the same failure in the words every surface already has for one. Nobody is shown a send overview for a send that cannot happen.

8. **The mode is a line that says what holds, not a control.** The settings name the state the user's own choices amount to: no model yet; Cloud (a provider answers, this device computes nothing itself); Hybrid (a provider answers, this device computes search by meaning, reads e-mails and appointments, writes gists); a model on this device answers — *without a promise*, because another profile, the internet or an external tool can still reach out; and Fully local. Under the switch stands what rests — only what is set up, each with what resting means for it —, or what is missing: without a model on this device the assistant cannot answer, and the card offers the way to one. One view model (`modeFacts`) for the desktop's card and the phone's group.

9. **The native side holds the rule once more.** The web view tells its shell what the switch says when the settings are read and whenever it changes. On the desktop a flag in `ai_egress.rs` makes `ai_http` answer a request for an endpoint that is not this computer before a key is read, and `not_while_local` refuses in every other command that sends something for the assistant or starts a program for it — the page fetch, the requests and programs of foreign servers and their sign-in, an agent's start and sign-in —, and the MCP server is configured as off. On the phone the same flag is read by the egress plugin, the page fetch and the plugins of foreign servers. This is a second check against a mistake in the web view's own code. It is no defence against a web view that was taken over, which could clear the flag the way it sets it; the native boundaries of [ADR 0017](0017-ai-harness-architecture-and-native-boundary.md) are what hold there.

10. **What the switch is not.** It is about the assistant. Sync, mail, calendars and updates are functions of their own with switches of their own. It is no rule of a note: "never to the cloud" on a note holds whether the switch is on or off ([ADR 0018](0018-ai-context-package-and-egress-policy.md)). And loading a package for search by meaning stays possible: a download the user starts, which carries nothing from the vault.

11. **A model on a server of this device is what its user says it is.** A profile's choice of such a model can carry two statements: its context window in tokens, and that it takes no tools. Neither is asked of a provider's model or of the system's own, which say both themselves, nor of a model that transcribes or embeds. A statement belongs to the pair of provider and model, wherever a profile makes it — a conversation knows its model, not the profile it was started from.

12. **No tools means none.** A conversation with such a model is begun without tools, without the catalog of skills that needs one, without the internet and without the memory's lookup. A conversation that was begun with tools goes on — a user who finds that a model cannot call them switches them off and asks again —, and the model then reads its words and its pictures (`withoutTools`): no tool is named, and what was called earlier and what came back stay in the record and are not sent again, because a result without its call is a message no chat endpoint takes. Two turns of one role that a call stood between become one message. This is how the system's own model already reads a conversation ([ADR 0021](0021-ai-local-inference-and-platform-models.md)).

13. **A stated window is kept, never guessed around.** The context package of a small window is made smaller by what the request carries anyway — its instructions, its tools, its earlier turns, room for an answer —, and no part of a small package is ever larger than the default one. And a request that cannot fit is not sent: the run stops with `window_too_small` and says what the request would take and what was stated, so the user can raise the window at the server and in the profile, switch the tools off, or leave notes out. It is checked before every call of a run — tool results grow a conversation within one —, and where a document goes to a reader on this device. Only a stated window is checked: a provider says "too long" itself. The count is an estimate on the cautious side; it can refuse a request that would just have fit, and never sends one that is cut.

14. **A model on this device is given time.** A server on a laptop's processor reads a long conversation for minutes and sends nothing until it has read it. The native egress of all three shells therefore lets a recipient on this device be silent for fifteen minutes where everyone else has three — by the same rule that says what "on this device" is (`silence_limit`, `AiNetRules.silenceSeconds`, the request's own limit on iOS). The conversation's waiting line says, after ten seconds without a word, where the thinking happens, and counts along; the count is hidden from a screen reader, which hears the line once. And two failures say what is the matter there: a server on this device that does not answer is not "unreachable" — the text asks whether it runs —, and one that falls silent is named with its two likely causes, that it stopped or that the model is too large for the device.

15. **The gate is a set of tests.** That no way reaches anyone but this device: a conversation, one that ran with a provider before, a connection test, the egress of search by meaning, the doors, a review, a foreign server offered or called, a conversation begun with a server's tools or with the internet, a request already under way (`aiLocalOnlyGate.test.ts`, with the session's cases for the internet and for agents). That the native sides hold it where they send (`aiLocalOnlyBoundary.test.ts`, the Rust and Android unit tests). That the mode line says what holds (`localMode.test.ts`), and that both shells show it.

## Consequences

- "Fully local" says what the app does: while it is on, the app itself opens no way to a provider, to the internet or to another program for the assistant. What it costs is said where it is switched on — the providers that receive nothing, the profiles that do not answer, the internet, the external tools. What a program under the computer's own address does with a request is that program's: a proxy the user put in front of a provider is "this device" to Plainva, which sees an address and not what stands behind it ([threat model](../engineering/AI_Threat_Model.md), residual risks).
- What a local model cannot do is not papered over. A small window gets fewer and shorter notes; a request that does not fit is refused with the numbers; a model without tools answers from what goes along.
- A server in the home network cannot be used while the switch is on. That is the meaning of the switch, not an oversight; whoever wants such a server leaves the switch off. To the state line it is a provider like any other that is not this device.
- The phone's native check was written without a device or a compiler at hand; the Labs build is where it is first built, and its rule (`AiNetRules.onThisDevice`) has a unit test there.
- Not part of this decision, and still open from the plan: packages for generation that Plainva loads and starts itself, the device check for them, transcription and photo capture without a network, and generation on the phone beyond the system's own model.

## Alternatives

- **Three segments: Cloud, Hybrid, Fully local** (the first mockup). Rejected: two of the three are no choice. A user who picks "Cloud" with a package loaded for search would be told something untrue, or the pick would have to switch the package off.
- **A check in every feature that sends.** Rejected: the list of doors grows with every part of the plan, and the one that is forgotten breaks the promise without a test noticing. One place every request passes needs no list.
- **Holding it natively only.** Rejected as the only place: the native side sees an endpoint, not why a request is made — the words a refusal needs, the state line and what rests are the session's. Kept as the second check (decision 9).
- **Counting the home network as local** (a private address range). Rejected: a private address is another device with its own users, logs and backups, and private ranges are what VPNs and company networks are made of.
- **Picking a model for the user when the switch goes on** (the first one found on the device). Rejected: a conversation would be answered by a model nobody chose, and the settings would have changed by themselves.
- **Letting an open conversation go on with the model on the device.** Rejected: its whole history — written with a provider's model, with its tool results — would go to another model without a question, and the record would say two things about who answered.
- **Asking the server for the window** (a model's details, a probe request). Rejected for now: no two servers answer alike, the surface they share has no such field, and what is loaded can differ from what is configured. A statement by the user is the one thing that is the same everywhere; a server that says it reliably can be read later without changing the model of the settings.
- **Shortening a request that is too long** (dropping the oldest turns). Rejected: that is the silent cut, made by Plainva instead of the server.
- **Sending earlier calls and results as plain text to a model without tools.** Rejected: what a stranger wrote would move from a tool's result into a message in the user's voice.
- **Refusing package downloads while the switch is on.** Rejected: the switch would prevent the very set-up that makes it usable, and a download carries nothing from the vault.
