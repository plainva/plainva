# 他のアプリからインポート

最終更新: 2026-07-28

Plainva は他のノートアプリからノートを取り込めます。インポートは必ず現在開いている保管庫の中の、自分で名前を付けたサブフォルダーに書き込まれます。保管庫のそれ以外の部分には手を触れないので、インポートしたフォルダーは後から他のフォルダーと同じように移動したり削除したりできます。

**インポートはデスクトップの機能です。**モバイルアプリはインポートできません。デスクトップで取り込めば、ほかのファイルと同じように同期を通じてスマートフォンに届きます。

## インポートを始める

入り口は2つあります。

- **コマンドパレット**（`Mod+P`）→ **他のアプリからインポート...**
- ファイルツリーで**フォルダーを右クリック** → **他のアプリからインポート...**

ウィザードは3ステップです。移行元のアプリを選び、エクスポートファイルを選ぶ（または Notion のトークンを入力する）、そして保存先フォルダーに名前を付けます。その後、ノートとデータベースの件数、そしてそのインポートで取り込めないものの一覧がプレビューされます。**インポートを開始**を押すまで、何も書き込まれません。

## インポートできるもの

| 移行元 | 選ぶもの | 取り込まれる内容 |
|---|---|---|
| **Notion（API）** | インテグレーショントークン | ページ、フォルダー階層、行を含むデータベース、リレーション、21種類のプロパティ型 |
| **Notion（ZIPエクスポート）** | ZIP ファイルまたは展開済みフォルダー | ページとフォルダー構造。データベースは**空**で作成されます |
| **Evernote（ENEX）** | 1つ以上の `.enex` ファイル | ノート、タグ、チェックリスト、作成日・更新日 |
| **Google Keep（Takeout）** | Takeout の ZIP または `.json` ファイル | ノート、チェックリスト、ラベル（タグとして）、色、固定・アーカイブ状態 |
| **Simplenote** | エクスポートした `.json` ファイル | 有効なノートとそのタグ |
| **Logseq** | グラフのフォルダー | ファイルをそのままコピー |
| **Markdownフォルダー / ZIP** | フォルダー、ファイル、または ZIP | `.md` ファイルとそのフォルダー構造 |

Obsidian 用のインポーターはありません。必要ないからです。Plainva は Obsidian の保管庫を直接開けます。**保管庫を開く**からフォルダーを選ぶだけです。

## Notion の詳細

2つの経路で結果が大きく変わるのは Notion だけです。

**インテグレーショントークンを使う場合（推奨）。** `notion.so/my-integrations` でトークンを作成します。次に Notion でインポートしたい各ページを開き、右上の **「...」** → **Connections（接続）** から作成したインテグレーションを追加してください。Notion は明示的に接続したページしか外部に公開しません。

API 経由なら、Plainva はテキストだけでなく**構造**を読み取れます。

- ページ階層がフォルダー構造になります。
- 各データベースが `.base` ファイルと、**1行につき1つのノート**が入ったフォルダーになります。
- **リレーションは双方向のウィキリンク**としてノート間に張られます。
- 21種類のプロパティ型に対応します——セレクト、ステータス、マルチセレクト、日付、数値、チェックボックス、URL、メール、電話番号、関数、ロールアップ、リレーション、ユーザー、一意のID など。
- データベースのスキーマからテーブル・ボード・カレンダー・リストの各ビューが生成されます。
- ページ内に埋め込まれたデータベースは、実際に動作する `![[Database.base]]` の埋め込みになります。

**ZIP エクスポートを使う場合。** トークンなしでオフラインでも使えますが、Notion のエクスポートにはデータベースのスキーマもページ ID も含まれていません。ページとフォルダーは取り込まれますが、データベースは**空の** `.base` ファイルとして作成され、レポートにもそう記載されます。データベースが重要なら API 経由を使ってください。

## インポートで取り込めないもの

各インポーターは自分の制限をプレビューで示し、レポートでも改めて記載します。主なものは次のとおりです。

- **添付ファイルと画像はインポートされません。** レポートに1つずつ記載されるので、エクスポート内に何が残るかが分かります。Evernote の添付ファイルや Keep の画像も同様にそこに残ります。
- **アーカイブ内の一部の項目は意図的にスキップされます。** 非常に大きなファイル、シンボリックリンク、安全でないパスを持つ項目です。インポートを開始する前に、プレビューに理由とともに表示されます。
- **非常に長い Notion ページ**は全文を読み取りますが、トグル・段組み・入れ子のリストの中にある内容は追いかけません。
- **Logseq のファイルはそのままコピーされます**——`key:: value` プロパティやブロック参照は Plainva のプロパティやリンクには変換されません。
- **Simplenote のゴミ箱**はスキップされます。
- **Notion の ZIP エクスポート**では空のデータベースが作成されます（上記参照）。

## 日付も取り込まれます

何年もかけて積み上げてきたコレクションは、インポート後にすべてが今日の日付になってしまうと、時間の流れが失われてしまいます。そのため Plainva は移行元の日付を引き継ぎます。

- インポートされたノートのフロントマターには `created` と `updated` として日付が書き込まれ、グラフの時間軸もここから日付を読み取ります。
- ファイル自体にも移行元の更新日時が設定されるので、日付順の並び替えや**最近開いた**が正しくなります。ファイルの作成日時は Windows でしか設定できません。他の OS ではフロントマターがその情報を担います。
- 移行元に日付がない場合、Plainva はエクスポートファイルの日付を使います。日付を勝手に作ることは決してありません——手がかりが何もなければ、その項目は空のままになります。

## 1件の失敗でインポート全体が止まることはありません

1つのノートを書き込めなくても、インポートは続行され、レポートに理由とともにそのノートが記載されます。実行が途中で止まった場合でも、レポートは書き込まれます——だから、すでに保管庫に入ったものを常に確認できます。

## 何も上書きされません

インポートは開いている保管庫に書き込むため、意図的に非破壊的に作られています。

- ノート名がすでに使われている場合、既存のものを置き換えるのではなく、インポートされたノートに**番号**が付きます（`Meeting (2).md`）。移行元の2つのノートが同じ名前を持つ場合も同様です。
- インポートされたノートには通常どおり OKF のフロントマター（`type`、`okf_version`）が付くため、`.base` のフィルターやビューの中で他の Plainva のノートとまったく同じように扱われます。
- 保存先サブフォルダーの外側は何も変更されません。

インポートを完全に分けておきたい場合は、先に新しい保管庫を作り（スタート画面の**新しい保管庫**）、そこへインポートしてください。

## インポートレポート

実行ごとに、保存先フォルダーに**インポートレポート**が書き込まれます。内容は次のとおりです。

- インポートされたノートとデータベースの件数
- このインポーターが原理的に取り込めないもの
- **不完全**に取り込まれたもの、**スキップ**されたもののすべてと、その理由
- すべてのファイルとその状態

レポートはその実行の正直な記録です。何かが途中で切れたり省かれたりした場合は、成功として黙って数えられるのではなく、必ずここに記載されます。エクスポートを削除する前に目を通してください。
