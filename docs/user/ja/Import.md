# 他のアプリからインポート

最終更新: 2026-07-28

Plainva は他のノートアプリからノートを取り込めます。インポートは必ず現在開いている保管庫の中の、自分で名前を付けたサブフォルダーに書き込まれます。保管庫のそれ以外の部分には手を触れないので、インポートしたフォルダーは後から他のフォルダーと同じように移動したり削除したりできます。

**インポートはデスクトップの機能です。**モバイルアプリはインポートできません。デスクトップで取り込めば、ほかのファイルと同じように同期を通じてスマートフォンに届きます。

## インポートを始める

入り口は3つあります。

- **スタート画面** → **他のアプリからインポート**——まだ保管庫を持っていないときの入り口で、アプリを乗り換える際の通常のケースです。
- **コマンドパレット**（`Mod+P`）→ **他のアプリからインポート...**
- ファイルツリーで**フォルダーを右クリック** → **他のアプリからインポート...**

最初のステップでは、エクスポートを尋ねられます——手元にあるものに応じて**ファイルを選択...**または**フォルダーを選択...**を使います。そのあとウィザードが認識したアプリの名前を示し、インポート先を決めます。続いて、今回の実行の件数、このインポートの制限、移行元向けのオプションを示すプレビューが表示されます。**インポートを開始**を押すまで、何も書き込まれません。

**エクスポートに合った項目がどれか、自分で分かっている必要はありません。** ファイルを選べば、Plainva が移行元を認識します——Notion のエクスポートはパス内の長い ID で、Logseq のグラフは `journals/` と `pages/` フォルダーで、Keep や Simplenote のエクスポートは JSON の中身で見分けます。ウィザードは認識した内容を表示します。認識が間違っていた場合は、上のリストで変更すれば、その選択のまま進みます。

## インポート先

インポートごとに、次のどちらか一方だけです——両方にはなりません。

- **新しい保管庫**: 空のフォルダーを選ぶと、Plainva はそこに新しい保管庫を作成してインポートします。すでに持っているものには一切触れられず、インポート全体を取り消すには、そのフォルダーを削除するだけで済みます。Plainva を試してみる場合に適した選択です。
- **開いている保管庫のサブフォルダー**: すべてが、自分で名前を付けた新規作成の1つのサブフォルダーに収まります。保管庫の残りの部分には影響しません。

選択の下にある宛先の行は常に正確なフォルダーを示すので、どこに何が入るかを推測する必要は一切ありません。

## このインポートのオプション

プレビューには件数の下に、**認識した移行元に合ったスイッチ**が並びます——移行元ごとに独自のスイッチを持っており、その移行元にできないことは、そこに現れることもありません。もっと早い段階ではなく、この位置に置かれているのは、これから起きることが見えて初めて質問に意味が出てくるからです。件数を変えるスイッチを切り替えると、件数はすぐに再カウントされます。

- **インポート元の日付を維持する**（オン）——インポートされたノートは移行元の作成日と更新日を引き継ぎます。オフにすると、すべて今日の日付になります。
- **削除済みのノートも一緒にインポートする**（オフ）——エクスポートにゴミ箱が含まれる Google Keep と Simplenote 向けです。既定では、そこにあるものはそのまま残ります。レポートにその名前が記載されます。

## プレビューが示すもの

プレビューは何かが書き込まれる前の最後の確認地点で、後になって驚くはずのことをすべて示してくれます。

- 今回の実行の件数——ノートとデータベース、それに移行元にあれば**添付ファイル**と**チェックリスト**、
- 正確な保存先フォルダー、
- このインポーターが**取り込めない**もの、そしてアーカイブ内でスキップされた項目それぞれ、
- クラウド接続のある保管庫の場合、インポートしたノートが後で**アップロード**されるという案内、
- 非常に大きな移行元の場合、検索インデックスと初回同期にしばらく時間がかかるという案内。

## 実行を止める

大きなワークスペースには時間がかかるので、インポートは途中で止められます。実行中に**インポートを停止**を押してください。すでに保管庫に届いたものはそのまま残り、レポートにもそう記載されます——途中までのインポートは壊れたインポートではありません。完全なインポートのときと同じく、取り消す方法はそのフォルダーを削除することです。

## インポートできるもの

| 移行元 | 選ぶもの | 取り込まれる内容 |
|---|---|---|
| **Notion（API）** | インテグレーショントークン | ページ、フォルダー階層、行を含むデータベース、リレーション、21種類のプロパティ型 |
| **Notion（ZIPエクスポート）** | ZIP ファイルまたは展開済みフォルダー | ページとフォルダー構造。データベースは**空**で作成されます |
| **Evernote（ENEX）** | 1つ以上の `.enex` ファイル | ノート、タグ、チェックリスト（チェック済み・未チェック）、作成日・更新日 |
| **Google Keep（Takeout）** | Takeout の ZIP または `.json` ファイル | ノート、チェックリスト、ラベル（タグとして）、色、固定・アーカイブ状態 |
| **Simplenote** | エクスポートした `.json` ファイル | 有効なノートとそのタグ |
| **Logseq** | グラフのフォルダー | ファイルをそのままコピー |
| **Markdownフォルダー / ZIP** | フォルダー、ファイル、または ZIP | `.md` ファイルとそのフォルダー構造 |

**Obsidian** も一覧に含まれていますが、インポートは何も始まりません——そもそも必要ないからです。Plainva は同じ Markdown ファイルを扱います。この項目はそのことを説明し、**保管庫を開く** を提示します。ウィキリンク、タグ、フロントマター、`.base` ファイルはそのまま機能し続け、保管庫は Obsidian でも引き続き使えます。正直に言うと、プラグインのエコシステムも、Canvas も、Dataview もありません——代わりに `.base` のフィルターが使えます。ノート内のプラグイン構文はそのままプレーンテキストとして残ります。

## Notion の詳細

2つの経路で結果が大きく変わるのは Notion だけです。

**インテグレーショントークンを使う場合（推奨）。** `notion.so/my-integrations` でトークンを作成します——ウィザードが3つの手順を示し、そのページを開いてくれます。次に Notion でインポートしたい各ページを開き、右上の **「...」** → **Connections（接続）** から作成したインテグレーションを追加してください。Notion は明示的に接続したページしか外部に公開しません。

**Plainva はトークンを保存しません。** その回のインポートだけに使われ、その後は消えます。接続済みのアカウントが作られることもありません。次回インポートする際は、もう一度貼り付けてください。

API 経由なら、Plainva はテキストだけでなく**構造**を読み取れます。

- ページ階層がフォルダー構造になります。
- 各データベースが `.base` ファイルと、**1行につき1つのノート**が入ったフォルダーになります。
- **リレーションは双方向のウィキリンク**としてノート間に張られます。
- 21種類のプロパティ型に対応します——セレクト、ステータス、マルチセレクト、日付、数値、チェックボックス、URL、メール、電話番号、関数、ロールアップ、リレーション、ユーザー、一意のID など。
- データベースのスキーマからテーブル・ボード・カレンダー・リストの各ビューが生成されます。
- ページ内に埋め込まれたデータベースは、実際に動作する `![[Database.base]]` の埋め込みになります。

**ZIP エクスポートを使う場合。** トークンなしでオフラインでも使えますが、Notion のエクスポートにはデータベースのスキーマもページ ID も含まれていません。ページとフォルダーは取り込まれ、**インポートしたページ同士のリンクは引き続き機能します**——Notion はパスの各セグメントに長い ID を書き込んでおり、Plainva はそれを実際に書き込んだノートに結び付けます。データベースは**空の** `.base` ファイルとして作成され、レポートにもそう記載されます。データベースが重要なら API 経由を使ってください。

## インポートで取り込めないもの

各インポーターは自分の制限をプレビューで示し、レポートでも改めて記載します。主なものは次のとおりです。

- **Notion の添付ファイルは API 経由でインポートされます。** Notion のファイルリンクは署名付きで1時間以内に失効するため、Plainva はインポート中にダウンロードし、インポート先の `Attachments` フォルダーに置きます。ページがウェブ上の別の場所から読み込んでいる画像はリンクのまま残ります。ほかのソースではファイルは元の場所に残ります。ZIP エクスポート内の添付ファイル、Evernote の添付ファイル、Keep の画像はエクスポート内に残り、レポートに1つずつ記載されます。
- **アーカイブ内の一部の項目は意図的にスキップされます。** 非常に大きなファイル、シンボリックリンク、安全でないパスを持つ項目です。インポートを開始する前に、プレビューに理由とともに表示されます。
- **非常に長い Notion ページ**は全文を読み取りますが、トグル・段組み・入れ子のリストの中にある内容は追いかけません。
- **Logseq のファイルはそのままコピーされます**——`key:: value` プロパティやブロック参照は Plainva のプロパティやリンクには変換されません。
- **削除したノートは削除されたままです。** Simplenote と Google Keep のゴミ箱はスキップされます——一度手放すと決めたノートを、インポートが黙って戻すべきではないからです。レポートには名前入りで記載されるので、何が残されたかを確認できます。
- **Notion の ZIP エクスポート**では空のデータベースが作成されます（上記参照）。

## 日付も取り込まれます

何年もかけて積み上げてきたコレクションは、インポート後にすべてが今日の日付になってしまうと、時間の流れが失われてしまいます。そのため Plainva は移行元の日付を引き継ぎます。

- インポートされたノートのフロントマターには `created` と `updated` として日付が書き込まれ、グラフの時間軸もここから日付を読み取ります。
- ファイル自体にも移行元の更新日時が設定されるので、日付順の並び替えや**最近開いた**が正しくなります。ファイルの作成日時は Windows でしか設定できません。他の OS ではフロントマターがその情報を担います。
- 移行元に日付がない場合、Plainva はエクスポートファイルの日付を使います。日付を勝手に作ることは決してありません——手がかりが何もなければ、その項目は空のままになります。

## 1件の失敗でインポート全体が止まることはありません

1つのノートを書き込めなくても、インポートは続行され、レポートに理由とともにそのノートが記載されます。実行が途中で止まった場合でも、レポートは書き込まれます——だから、すでに保管庫に入ったものを常に確認できます。

## 何も上書きされません

インポートは開いている保管庫に書き込むため、意図的に非破壊的に作られています。

- ノート名がすでに使われている場合、既存のものを置き換えるのではなく、インポートされたノートに**番号**が付きます（`Meeting (2).md`）。移行元の2つのノートが同じ名前を持つ場合も同様です。
- インポートされたノートには通常どおり OKF のフロントマター（`type`、`okf_version`）が付くため、`.base` のフィルターやビューの中で他の Plainva のノートとまったく同じように扱われます。
- 保存先サブフォルダーの外側は何も変更されません。

インポートを完全に分けておきたい場合は、先に新しい保管庫を作り（スタート画面の**新しい保管庫**）、そこへインポートしてください。

## インポートレポート

実行ごとに、保存先フォルダーに**インポートレポート**が書き込まれます。内容は次のとおりです。

- インポートされたノートとデータベースの件数
- このインポーターが原理的に取り込めないもの
- **不完全**に取り込まれたもの、**スキップ**されたもののすべてと、その理由
- すべてのファイルとその状態

レポートはその実行の正直な記録です。何かが途中で切れたり省かれたりした場合は、成功として黙って数えられるのではなく、必ずここに記載されます。エクスポートを削除する前に目を通してください。

一番下には、インポートを**取り消す**方法が書かれています。1回の実行によるものはすべて1つのフォルダーにまとまっているので、そのフォルダーを削除すればインポートは消えます。**新しい保管庫**を先とした場合は、その新しい保管庫自体のフォルダーがそれに当たります。そのための専用の取り消しコマンドは必要ありません。レポート自体も普通のノートなので、読み終えたら削除して構いません。
