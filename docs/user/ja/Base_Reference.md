# データベースリファレンス (.base)

最終更新: 2026-11-03

このページでは、`.base`ファイルに含められるすべての内容と、Plainvaがそれぞれの部分をどう扱うかを一覧にしています。すべてのトップレベルキー、すべてのフィルター形式、オプション付きのすべてのビューの種類、集計、並べ替え、制限、Plainvaが知らないキーがどうなるか、そしてPlainvaがObsidian Basesと異なる動作をする点です。Obsidianのドキュメントではなく、Plainvaのコードが現在読み取り、評価し、書き込む内容を説明しています。

日常的な使い方は、まず[データベース (.base)](Databases_Base.md)をお読みください。ツールが保管庫のファイルを直接書き込むときに守るべきルールと、リレーションの完全な例は、[ファイル形式リファレンス](File_Format_Reference.md)にあります。

## 概要

| ファイルの部分 | Plainvaの動作 |
|---|---|
| `filters` | [フィルター](#フィルター)に挙げたソース（フォルダー、タグ）と条件を読み取って適用します |
| `views` | 8種類すべてのビュー、その順序、並べ替え、フィルター、集計を読み取ります |
| `properties` | 列のスキーマ、表示名、Plainvaの`plainva`ブロックを読み取ります |
| `summaries`（ビュー） | 14個の組み込み集計を計算します |
| `formulas` | ファイルに保持しますが、計算しません |
| `summaries`（トップレベル） | カスタム集計式を保持しますが、計算しません |
| `this` | まだ対応していません |
| その他のキー | ファイルに保持します（[Plainvaが知らないキー](#plainvaが知らないキー)を参照） |

## トップレベルのキー

`.base`ファイルは、次のトップレベルキーを持つYAMLです。いずれも省略可能で、`views`のないファイルは1つのテーブルとして開きます。

| キー | 内容 | Plainvaでの扱い |
|---|---|---|
| `filters` | どのノートがデータベースに属するか（ソース） | 読み取って適用します |
| `properties` | 列ごとに1エントリー、キーはプロパティID | 読み取ります。Plainvaの追加分は`plainva`ブロックにあります |
| `views` | ビューのリスト | 読み取ります。すべてのビューに`name`が必要です |
| `formulas` | Obsidianの数式、`name: expression` | そのまま保持し、計算しません |
| `summaries` | Obsidianのカスタム集計式 | そのまま保持し、計算しません |

Plainvaは他のトップレベルキーを書き込みません。Obsidianは知らないキーのある`.base`を開くことを拒否するためです。ごく古いPlainvaが書き込んだトップレベルの`columns:`キーは今でも読み取られ、ファイルを次に保存するときに`properties`へ移されます。

## プロパティ (`properties`)

### プロパティID

プロパティIDは列に名前を付けます。3種類あります。

| ID | 意味 | 例 |
|---|---|---|
| `note.<key>` | ノートのFrontmatterのキー | `note.status` |
| `file.<field>` | ファイルに関する事実（[ファイルフィールド](#ファイルフィールド-file)を参照） | `file.mtime` |
| `formula.<name>` | `formulas`にあるObsidianの数式 | `formula.price_per_unit` |

`properties`のキー、ビューの`order`、`sort[].property`はこれらのIDを使います。フィルター式の中と`plainva`ブロックの中では、Frontmatterのキーは接頭辞なし（`status`）で書きます。フィルター式は`note.status`も理解します。

ノートがキーを列と異なる大文字小文字で書いている場合（列`due`に対して`Due`）でも、Plainvaはその列に値を表示し、変更はノート自身の綴りで書き戻します。

### 表示名

`properties.<id>.displayName`はObsidianの列ラベルです。Plainvaはこれを列見出しとして表示し、保持します。これがない場合、Frontmatterのキーは先頭を大文字にして表示されます（画面上のみ）。ファイルフィールドには独自の名前があり、たとえば**名前**、**更新日時**、**サイズ**、**パス**、**To-doリスト**、**ファイル名からの日付**です。

### 列の`plainva`ブロック

列に対するPlainvaの追加分は、すべて`properties.<id>.plainva`の下にあります。Obsidianはこれを無視します。

| キー | 値 | 意味 |
|---|---|---|
| `input` | フィールドタイプ（下記のリスト） | 列のフィールドタイプ |
| `ratingMax` | 数値、1〜10 | 評価のマークの数（既定は5） |
| `ratingGlyph` | 1文字 | 評価が描くマーク（既定は点） |
| `options` | 選択肢のリスト | 選択、ステータス、複数選択の固定値 |
| `relationBase` | 保管庫相対の`.base`パス | リレーションが指すデータベース |
| `relationLimit` | `one` | リレーションはちょうど1件のリンクを持ちます。なければ上限なしです |
| `reverseOf` | `{ base, property }` | 計算される逆リレーション列 |
| `rollup` | `{ through, of, fn, where }` | 計算されるロールアップ列（[ロールアップ](#ロールアップ)を参照） |
| `previousKeys` | 最大8個の以前の名前のリスト | 名前を変更した列をコメントが再び見つけられるようにします |

### フィールドタイプ (`input`)

`text`, `number`, `rating`, `checkbox`, `date`, `datetime`, `select`, `status`, `multiselect`, `list`, `tags`, `url`, `email`, `phone`, `relation`.

古い綴り2つも読み取られます。`multi-select`は`multiselect`として、`link`は`relation`として扱われます。`input`のない列、またはこのリストにない値を持つ列は、ノートの値からタイプが決まります。`true`/`false`はチェックボックス、数値は数値、`[[links]]`のリストはリレーション、`2026-07-03`は日付、Webアドレスは URL、などです。逆リレーション列とロールアップ列には`input`がありません。

### 選択肢と色

選択肢は`{ value, label, color, group }`で、必須なのは`value`だけです。`color`はパレット名`gray`、`teal`、`blue`、`green`、`amber`、`coral`、`purple`、`pink`のいずれかで、未知の名前は値から導かれる色にフォールバックします。`group`は**ステータス**でのみ使われ、同じグループの選択肢が1つの段階を成します。単なる文字列は、その値を持つ選択肢として読み取られます。

### ロールアップ

ロールアップ列は、このデータベースのリンク列が指すノートから値を計算します。値はどのファイルにも保存されません。

- `through` — このデータベースのリレーション列または逆リレーション列。
- `of` — リンク先ノートのプロパティ。`count`には不要です。
- `fn` — `count`、`countWhere`、`percentWhere`、`sum`、`average`、`median`、`min`、`max`、`earliest`、`latest`、`checked`、`unchecked`、`empty`、`filled`、`unique`のいずれか。
- `where` — `{ op, value }`。`countWhere`と`percentWhere`に必須で、`op`は`==`、`!=`、`contains`、`notContains`、`>`、`<`、`>=`、`<=`のいずれかです。`value`が空なら「空である」を意味します。

必要な部分が欠けているロールアップ、またはこのリストにない関数を指定したロールアップは無視されます。列は空のままで、データベースは開きます。別の計算列を経由するロールアップも空のままです。

## ファイルフィールド (`file.*`)

これらの値はFrontmatterではなく、ファイルから得られます。データベースの各行は次を持ちます。

| フィールド | 値 |
|---|---|
| `file.name` | ノートの`title`プロパティがあればそれ、なければ`.md`を除いたファイル名 |
| `file.path` | 保管庫相対のパス |
| `file.mtime` | 最終更新、ミリ秒 |
| `file.ctime` | 作成、ミリ秒（ファイルシステムが報告する場合） |
| `file.size` | バイト単位のサイズ |
| `file.tags` | ノートのすべてのタグ（Frontmatterと本文）、それぞれ`#`付き。フィルター、ピンボード、またはその列を表示するか並べ替えに使うビューが必要とするときに入力されます |
| `file.tasks` | チェックボックスの進捗を`done/total`で表したもの。ボードと、その列を表示するビューで入力されます |
| `file.day` | デイリーノートのファイル名が表す日。保管庫のフォルダーと形式に従います。読み取り専用で、カレンダーまたはタイムラインの日付フィールドだけが使えます |
| `file.revision` | 内部の変更マーカー。当てにしないでください |

`file.folder`はソースとして機能します（[ソース](#ソース)を参照）が、列ではありません。`file.basename`、`file.ext`、`file.links`、`file.backlinks`、`file.embeds`、`file.properties`、`file.file`は提供されません。これらのいずれかを使う列は空のままで、フィルターはそれらを空として読み取ります。

## フィルター

### フィルターの置き場所

トップレベルの`filters`は**ソース**——どのノートがデータベースに属するか——を保持します。各ビューは、そのビューだけを絞り込む条件を持つ独自の`filters`を持てます。Plainvaは条件をそこに書き込みます。両方のレベルが一緒に適用されます。ファイルがトップレベルに残した条件も引き続き機能し、Plainvaでの次の保存でそれらは各ビューに移されます。

### ソース

| ソース | 式 |
|---|---|
| フォルダー | `file.folder == "Projects/Active"` — そのフォルダーとすべてのサブフォルダー。`""`と`"/"`は保管庫全体です |
| タグ | `file.hasTag("project")` — ノートがまさにこのタグを持ちます。先頭の`#`は無視されます |

複数のソースは、他の条件と同様に`and`または`or`で組み合わせます。ソースのないデータベースは保管庫のすべてのノートを含みます。添付ファイル、予約された`index.md`と`log.md`、名前がドットで始まるファイルやフォルダーは、決して行になりません。

### 条件

条件は文字列です。値は二重引用符で囲み、`\"`と`\\`がそれぞれ引用符とバックスラッシュをエスケープします。プロパティはそのまま、または`note.`を付けて書きます。

| 条件 | 式 |
|---|---|
| が次と一致する | `status == "Done"` |
| が次と一致しない | `status != "Done"` |
| に次を含む | `contains(labels, "urgent")` または `labels.contains("urgent")` |
| に次を含まない | `!contains(labels, "urgent")` または `!labels.contains("urgent")` |
| より大きい、より小さい | `effort > "3"`、`effort < "8"` |
| 以上、以下 | `due >= "2026-07-01"`、`due <= "2026-07-31"` |
| が空である | `status == ""` または `status.isEmpty()` |
| が空でない | `status != ""` または `!status.isEmpty()` |
| タグを持つ | `file.tags.contains("#work")`、`!`で否定します |
| ヘッダーの色、アイコン | `note.plainva.header_color == "#2a7f7b"`、`note.plainva.icon == "lucide:pin"` |

### 値の比較方法

- **が次と一致する**と**が次と一致しない**はテキストを比較します。リスト（タグ、複数選択、リレーション）では、**が次と一致する**は「リストにこのエントリーがある」、**が次と一致しない**は「ない」を意味します。プロパティのないノートは**が次と一致する**には決して一致せず、**が次と一致しない**には常に一致します。
- **に次を含む**は、値の中、またはリストの各エントリーの中にテキストを探します。リストに対する`labels.contains("x")`は、ちょうど`x`であるエントリーを求めます。`file.tags`では両方の形式がタグ全体を求めるため、`#work`は`#workshop`や`#work/child`には一致しません。
- **より大きい**、**より小さい**、**以上**、**以下**は、両側が数値なら数値として、そうでなければテキストとして比較します——これによりISO日付（`2026-07-03`）が正しい順序になります。値のないノートはこれらには決して一致しません。
- **が空である**は、存在しないプロパティ、空の値、空のリストに一致します。
- チェックボックスは`"true"`または`"false"`として比較されます。

### `and`、`or`、`not`

`filters`オブジェクトは、各レベルで`and`、`or`、`not`のうちちょうど1つを持ちます。そのエントリーは条件の文字列、またはさらなるフィルターオブジェクトです。

| キー | 一致する条件 |
|---|---|
| `and` | すべてのエントリーが一致するとき |
| `or` | 少なくとも1つのエントリーが一致するとき |
| `not` | どのエントリーも一致しないとき |

Plainvaは任意の深さを評価します。フィルターパネルは、**すべて**または**いずれか**の下にあるグループを1レベル編集できます（**グループを追加**）。それより深い構造は **複雑なフィルター（編集不可）** と表示され、ファイルに残り、適用されます。その中にPlainvaが読み取れない条件があれば、その下に適用されていないことが示されます。1つのレベルに`and`と`or`が並んでいる古いファイルは「`and`のすべてと`or`の1つ」として読み取られ、次の保存で有効な形式で書き込まれます。

### Plainvaが読み取れないもの

上の2つの表にある形式だけが理解されます。それ以外——`file.inFolder(…)`、`file.hasLink(…)`、`file.hasProperty(…)`、引用符のない数値（`price > 2`）、1つの文字列内の`&&`と`||`、算術、`now()`のような日付関数、`this`——はファイルに残り、フィルターパネルには書かれたとおりに表示され、 **適用されていません：Plainvaはこの条件を読み取れないため、何も絞り込みません。** という注記が付きます。そのためビューには、Obsidianで同じフィルターが表示するより多くのノートが表示されます。

## 数式

PlainvaはObsidianの数式を計算しません。`formulas`はファイルにそのまま残り、ビューの`order`にある`formula.<name>`列は値なしで表示されます。**テーブルをエクスポート** → **数式 (.base)** は、Obsidianが計算できるように一部のロールアップを数式として書き込みます（[データベース (.base)](Databases_Base.md)を参照）。

## ビュー

### すべてのビューのキー

| キー | 値 | Plainvaでの扱い |
|---|---|---|
| `type` | `table`、`list`、`cards` | ビューの種類。次の表を参照 |
| `name` | テキスト | 必須。名前のないビューには、Plainvaが保存時に名前を付けます |
| `order` | プロパティIDのリスト | 表示する列、この順序で |
| `sort` | `{ property, direction }`のリスト | 並べ替えルール、`ASC`または`DESC` |
| `filters` | フィルターオブジェクト | ビュー独自の条件 |
| `summaries` | プロパティID → 集計名のマップ | 各列のフッター |
| `plainva` | マップ | Plainvaのビューオプション（下記） |

### 8種類のビュー

Obsidianが知っているのは`table`、`list`、`cards`です。Plainvaのその他のビューの種類は`type: table`と`plainva.render`として保存されるため、Obsidianではテーブルとして表示されます。

| ビューの種類 | ディスク上の`type` | `plainva.render` |
|---|---|---|
| **テーブル** (`table`) | `table` | — |
| **リスト** (`list`) | `list` | — |
| **ギャラリー** (`gallery`) | `cards` | — |
| **ボード** (`board`) | `table` | `board` |
| **カレンダー** (`calendar`) | `table` | `calendar` |
| **タイムライン** (`timeline`) | `table` | `timeline` |
| **グラフ** (`graph`) | `table` | `graph` |
| **ピンボード** (`pinboard`) | `table` | `pinboard` |

ボード、カレンダー、タイムライン、グラフ、ピンボードは、 **.baseファイルへのPlainva拡張機能を許可** がオンの間だけ**ビューの種類**として提示されます。Plainvaが知らない`type`はテーブルとして表示され、別の**ビューの種類**を選ぶまで書かれたとおりにファイルに残ります。

### ビューのオプション (`views[i].plainva`)

`plainva`ブロックの中では、プロパティは`note.status`ではなく接頭辞なし（`status`）で書きます。

| キー | ビューの種類 | 値 |
|---|---|---|
| `render` | ボード、カレンダー、タイムライン、グラフ、ピンボード | ビューの種類。上記を参照 |
| `groupBy` | ボード | 列の元になるプロパティ。ない場合は、ビューのObsidian独自の`groupBy`のプロパティ |
| `boardLaneBy` | ボード | **スイムレーンの基準**用の2つ目のプロパティ |
| `boardWipLimits` | ボード | 列の値→最大カード数（**WIP上限**）のマップ。0より大きい整数 |
| `boardColorMode` | ボード | `column`は列全体を着色します。なし = 見出しのチップのみ |
| `boardColumnOrder` | ボード | 列の手動順序。`__UNGROUPED__`は値のない列です |
| `colorBy` | ボード、タイムライン | カードとバーがこのプロパティの選択肢の色を取ります（**色の基準**） |
| `dateField` | カレンダー、タイムライン | 開始日（**日付フィールド**、**開始日**）。日付プロパティまたは`file.day` |
| `endField` | カレンダー、タイムライン | **終了日** |
| `coverImage` | ギャラリー | **カバー画像**を保持するプロパティ |
| `subItemsProperty` | テーブル | **サブアイテム**の親リレーション |
| `widths` | テーブル | 列→幅（ピクセル）のマップ |
| `dateFormat` | すべて | `long`、`iso`、`relative`。なし = 既定の短い形式 |
| `graphEdges` | グラフ | エッジとして描かれるリレーションプロパティ |
| `graphColorBy` | グラフ | ノードを着色する選択またはステータスのプロパティ |
| `graphSizeBy` | グラフ | ノードの大きさを決める数値プロパティ |
| `graphShowExternal` | グラフ | `true`はビューの外にあるリンク先も表示します |
| `graphShowIncoming` | グラフ | `true`は他のデータベースから来るリンクも表示します |
| `pinboardOrder` | ピンボード | 固定されていないカードのパス、手動順序 |
| `pinboardPinned` | ピンボード | 固定されたカードのパス、順序どおり |
| `pinboardFilterBy` | ピンボード | **ラベルのソース**: 複数選択プロパティ。なし = タグ |

### ファイル全体のオプション (最初のビューのみ)

これらのキーはデータベース全体に属します。Plainvaは最初のビューの`plainva`ブロックにのみ書き込み、それぞれの最初の有効な値を読み取ります。

| キー | 値 |
|---|---|
| `fileIconColor` | データベースアイコンの16進カラー（**データベースアイコンの色**） |
| `newItemFolder` | **エントリー**が新しいエントリーを保存するフォルダー |
| `newItemTemplate` | 新しいエントリー用のテンプレート |
| `contextFilters` | 埋め込まれたデータベースを、それが埋め込まれたノートに限定するプロパティ（**このノート**） |
| `taskList` | 新しいタスクも作成されるアカウントとリスト（`"<account id> <list id>"`） |

## 集計

`views[i].summaries`は列を次の名前のいずれかに対応づけます。フッターは、ビューが表示する行に対してそれを計算します。

| 名前 | Plainvaでの表示 | 結果 |
|---|---|---|
| `Average` | **平均** | 数値の平均 |
| `Min` | **最小** | 最小の数値 |
| `Max` | **最大** | 最大の数値 |
| `Sum` | **合計** | 数値の合計 |
| `Range` | **範囲** | 最大の数値から最小の数値を引いた値。日付では日数の差 |
| `Median` | **中央値** | 数値の中央の値 |
| `Stddev` | **標準偏差** | すべての数値の標準偏差（母集団） |
| `Earliest` | **最も早い** | 最も早い日付 |
| `Latest` | **最も遅い** | 最も遅い日付 |
| `Checked` | **チェック済み** | 値が`true`または`yes`の行 |
| `Unchecked` | **未チェック** | その他すべての行 |
| `Empty` | **値なし** | 値のない行 |
| `Filled` | **値あり** | 値のある行 |
| `Unique` | **異なる値** | 異なる値の数。リストのエントリーは1つずつ数えます |

数値は小数点以下2桁に丸められ、小数点のカンマも読み取られます。使える値のない列は、0ではなくフッターなしで表示されます。それ以外の名前は、トップレベルの`summaries`にあるカスタム式です。Plainvaはそれを保持し、メニューに **カスタム: …** と表示しますが、値は計算しません。

## 並べ替えとグループ化

- **並べ替え** — `sort`はルールのリストで、最初のルールが最初に決め、次のルールは同値の行の間でのみ決めます。数値は数値として、それ以外はテキストとして並べ替えられます（ISO日付は正しい順序になります）。値のない行は、どちらの方向でも最後に来ます。ルールがない場合は、最近変更されたノートが先頭に来ます。Plainvaは`property`の代わりに`field`も読み取り、`asc`/`desc`は大文字小文字を問いません。
- **グループ化** — ボードは`plainva.groupBy`でグループ化し、スイムレーンは`plainva.boardLaneBy`で分けます。代わりにObsidian独自の`groupBy`を持つビューは、そのプロパティでボードをグループ化し、グループ化の変更もそこに書き込まれます（その`direction`はそのまま残ります）。Plainvaはそれでテーブルをグループ化しません。

## データベースの埋め込みと`this`

ノート内の`![[Projects.base]]`は、閲覧ビューでもエディターでも、データベースをノートの中に表示します。`#`の後の部分（`![[Projects.base#Board]]`のようなビュー名）は無視され、埋め込みはそのデータベースで最後に使ったビューを表示します。ノート内の ` ```base ` コードブロックは、データベースではなくコードとして表示されます。

**`this`はまだ対応していません。** `this`を使うフィルターや数式はファイルに残りますが、Plainvaは評価しません。最もよくあるケース「このノートに属するエントリーを表示する」は、2つの仕組みでカバーされます。`contextFilters`（フィルターパネルの**このノート**）は、リレーションプロパティを通じて、埋め込まれたデータベースをそれが埋め込まれたノートに限定します。また、ホストノートのデータベースとリレーションを持つ埋め込みデータベースは、**このデータベースを現在のノートで絞り込む**を自動的に提供します。どちらもPlainvaの中でのみ働き、Obsidianはすべての行を表示します。

## 制限

- Obsidianのビューの`limit`は保持されますが適用されません。ビューはすべての行を表示します。
- フィルターパネルはフィルターグループを1レベル編集します。それより深いものは適用されますが、そこでは削除することしかできません。
- フィルター値は二重引用符で囲む必要があります（[Plainvaが読み取れないもの](#plainvaが読み取れないもの)を参照）。
- フォルダーソースは常にサブフォルダーを含みます。
- `ratingMax`は1〜10で描かれ、`previousKeys`は最大8個の名前を保持し、**WIP上限**は0より大きい整数のみを受け付け、`relationLimit`は`one`しか知りません。
- ロールアップは別の計算列の上では計算できません。

## Plainvaが知らないキー

Plainvaは`.base`を読み、アプリで変更した部分だけを変え、ファイル全体を新しく書き込みます——LF改行でBOMなしのYAMLとして。そのため、手書きファイルのコメントや間隔は保持されません。知らないものについては次のとおりです。

- **保持されるもの**: その他のトップレベルキー、`formulas`、トップレベルの`summaries`、`displayName`と`properties`エントリーのその他すべてのキー、列またはビューの`plainva`ブロック内の未知のキー、Plainvaが読み取れないロールアップ、Plainvaが使わないビューのキー（`limit`、`image`、…）、Plainvaが知らないビューの種類、そして読み取れないフィルター条件。Plainvaが理解できるが変更していない値は、ファイルの書き方を保ちます（`status`または`note.status`、プレーンテキストで書かれた選択肢）。
- **書き直されるもの**: Plainva自身の古い形式だけです——トップレベルの`columns:`マップは`properties`に移り、1つのレベルに並んだ`and`と`or`は有効な形式になり、非常に古いバージョンが`type: board`として保存したビューは`plainva.render`付きの`type: table`になります。
- **位置**: ビューが保持するキーはそのビューに属します。Plainvaでビューを削除または移動するとキーも一緒に移り、**複製**は新しいビューにそれらをコピーします。

## Obsidian Basesとの違い

| 項目 | Obsidian | Plainva |
|---|---|---|
| 数式、カスタム集計 | 計算される | 保持するが計算しない |
| `this` | 対応 | まだ対応していません |
| フィルター式 | 完全な式言語 | [条件](#条件)の形式 |
| `file.folder == "X"` | `X`の直下のノートのみ | `X`とそのすべてのサブフォルダー |
| `file.hasTag("x")` | `#x/child`も含む | ちょうど`#x` |
| `file.name` | ファイル名 | ノートに`title`プロパティがあればそれ |
| ビューの`limit`、`groupBy` | 適用される | `limit`は保持するが適用しない。`groupBy`はボードをグループ化するが、テーブルはグループ化しない |
| ビューの種類 | `table`、`list`、`cards`とプラグインの種類 | 8種類。未知のものはテーブルとして表示され、ファイルに保持される |
| `![[db.base#View]]` | そのビューを開く | 最後に使ったビュー |
| ` ```base ` コードブロック | データベース | コードブロック |
| Plainvaの`plainva`ブロック | 無視される | ボード、カレンダー、タイムライン、グラフ、ピンボード、リレーション、ロールアップ、フィールドタイプ |
