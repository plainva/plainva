# スクリプト（ベータ版）

最終更新: 2026-10-08

スクリプトは小さなプログラムで、数える、並べ替える、比べる、合計するといった、モデルは苦手でもプログラムなら毎回同じようにこなせる作業に向いています。JavaScriptで書きます。Plainvaの中の閉じた環境で動き、ファイルを開くことも、ネットワークに接続することも、時間を置いて待つこともできません。呼び出せるのは、チェックを入れたツールだけです。それらのツールは、AIが使うツールと同じ方法で保管庫を読むか、提案を残します。提案を適用するかどうかは、あなたが決めます。スクリプトが自分で何かを変更することはありません。

## スクリプトを実行する

スクリプトは、AIタブの**スキル**（スマートフォンでは**会話 → スキル**）にある**スクリプト**グループに表示されます。**実行**を選ぶとスクリプトが開くので、求められた内容を入力して**実行**を押します。実行中は、呼び出されたツールが1つずつ表示され、**停止**で終了できます。終わると、ダイアログに**呼び出し**、**結果**（コピーできます）、**ログ**に加えて、実行が上限のうちどれだけを使ったかが表示されます。

ここから開始した実行はこのデバイスの中だけで行われ、その内容がモデルに送られることはありません。そのため、クラウドに出さないノートも読めます。**試し実行**では、読み取るツールは呼び出されますが、アプリで何かを表示したり提案を残したりすることになる呼び出しは、記録されるだけです。

## 会話の中で

通常の会話では、AIは有効なスクリプトを見つけ、質問に合うときに実行できます。そのとき会話には**スクリプト「word-count」を実行しています**と表示されます。スクリプトが読めるのは、その会話が読んでよいものだけです。クラウドに出さないノートは出さないままで、スクリプトが読んだノートはすべて、その実行が読んだものとして数えられます。スクリプトが返すものは、データとしてモデルに渡され、指示として扱われることはありません。スキルで始めた会話にはスクリプトが提供されず、MCPサーバー経由で接続したAIアプリにも提供されません。

## 変更を提案する

スクリプトには、提案を行うツールを渡すこともできます。**ノートへの変更を提案**と**プロパティ値を提案**というツールは、ノートの余白に提案を置きます。**ノートの下書きを作成**、**データベースの項目の下書きを作成**、**タスクの下書きを作成**、**ジャーナルエントリの下書きを作成**というツールは、下書きを置きます。提案にも下書きにもスクリプトの名前が付き、提案を適用するか下書きを作成するまで保管庫は何も変わりません——AIの提案とまったく同じです。実行が終わると、ダイアログの**提案と下書き**の欄にそれらが一覧されます。**試し実行**で始めた実行は、何も残しません。

スクリプトが何を読んだかによって、提案や下書きを置ける場所が決まります。クラウドに出さないノートに基づく提案や下書きを受け付けるのは、同じルールが適用される場所だけです。会話では、その会話自身が提案できる場合にだけ、提案を行うスクリプトがAIに提供され、スクリプトがそこに残したものにはその会話のモデルの名前が付きます。

## スクリプトを書く

**新しいスクリプト**では、次の項目を入力します:

- **名前**——使えるのは小文字、数字、ハイフンです。この名前がフォルダー名になります。
- **説明**——何のためのスクリプトかを書きます。あなたもAIも、これで見分けます。
- **ツール**——スクリプトが呼び出してよいツールにチェックを入れます。**読み取り**の下には読み取るもの、**提案**の下には提案や下書きを残すものが並びます。スクリプトから見えるのは、チェックしたものだけです。
- **入力**——スクリプトが開始時に求めるもの。名前と、テキスト・数値・はい/いいえのどれか、そして必須かどうかを決めます。
- **上限**——計算時間（秒）、ツールの呼び出し回数、メモリ。
- **コード**——プログラム本体。

**作成して承認**を選ぶと、スクリプトが`.agent/scripts/<name>/`（`manifest.json`と`main.js`）として保管庫に書き込まれ、このデバイスで承認されます。スクリプトのメニューの**編集**で同じフォームが開き、**保存して承認**でファイルが置き換えられます。

コードは関数の本体です。`input`には入力が名前ごとに入り、`tools.<name>(…)`はツールを呼び出してその結果を待ち、`return`は結果を返し、`console.log(…)`はログに1行書き込みます。たとえば次のようになります:

```js
const found = await tools.search_vault({ query: "#" + input.tag, limit: 25 });
const notes = [];
for (const hit of found.results) {
  const note = await tools.read_note({ path: hit.path });
  if (note.text.includes("#" + input.tag)) notes.push(hit.path);
}
return { tag: input.tag, count: notes.length, notes };
```

言語はJavaScriptで、ES2020の水準です。`fetch`もタイマーも`import`もなく、ファイルにアクセスすることもできません。スクリプトが返すものは、JSONとして書き出せるデータでなければなりません。ツールが拒否した場合（存在しないノート、その会話が読んではいけないノートなど）は、スクリプトで受け止められるエラーが発生します。

## ツールが返す内容

フォームの**ツールが返す内容**でこのページが開きます。どのツールもオブジェクトを1つ受け取り、1つ返します。`cursor`には前の呼び出しの`next`を渡すと、そのリストの続きが返ります。

| ツール | 渡すもの | 返ってくるもの |
|---|---|---|
| `search_vault`——**保管庫の検索** | `query`、任意で`folder`、`limit`（最大25）、`cursor` | `results`: `{ title, path, snippet }`のリスト、`next` |
| `read_note`——**ノートの読み取り** | `path`、任意で`section`、`maxChars`（200〜20,000）、`cursor` | `path`、`text`、`next` |
| `get_outline`——**アウトラインの読み取り** | `path` | `path`、`properties`: 名前と値、`sections`: `{ level, text, section }`のリスト |
| `query_base`——**データベースの読み取り** | `base`（`.base`ファイルのパス）、任意で`view`、`limit`（最大50）、`cursor` | `base`、`view`、`views`、`rows`: `{ title, path, properties }`のリスト、`next` |
| `get_tasks`——**タスクの読み取り** | 任意で`range`（`today`、`upcoming`、`overdue`、`inbox`、`all`、`done`）、`limit`（最大50）、`cursor` | `tasks`: `{ state, title, due, priority, path, note, source }`のリスト、`next` |
| `get_backlinks`——**バックリンクを読んでいます** | `path`、任意で`limit`（最大50）、`cursor` | `path`、`notes`: `{ title, path, links, places }`のリスト、`next` |
| `graph_neighborhood`——**リンクをたどっています** | `path`、任意で`depth`（1または2）、`limit`（最大50） | `path`、`notes`: `{ title, path, fromHere, toHere, via }`のリスト |
| `get_recent`——**最近のノートを見ています** | 任意で`kind`（`opened`または`edited`）、`limit`（最大20） | `kind`、`notes`: `{ title, path, at }`のリスト |
| `get_calendar`——**予定を読んでいます** | `from`と`to`（`YYYY-MM-DD`の形式）、任意で`details`、`limit`（最大100） | `events`: `{ day, start, end, allDay, title, cancelled, place, with, others, online, event }`のリスト、`more` |
| `run_command`——**アプリの操作** | `id`（`open-note`、`show-in-graph`、`open-calendar`などのアプリのコマンド）、任意で`args`（`path`、`section`、`date`） | `done`、`command` |
| `propose_edit`——**ノートへの変更を提案** | `path`、`edits`（`{ find, replace }`のリスト）または`append`、任意で`section`、`note` | `proposed`、`path`、`passages` |
| `set_property`——**プロパティ値を提案** | `path`、`key`、`value`、任意で`note` | `proposed`、`path`、`property` |
| `create_note`——**ノートの下書きを作成** | `title`、`content`、任意で`folder` | `drafted`、`kind`、`title` |
| `create_entry`——**データベースの項目の下書きを作成** | `base`、`title`、任意で`properties`、`content` | `drafted`、`kind`、`title`、`base` |
| `create_task`——**タスクの下書きを作成** | `text` | `drafted`、`kind`、`title` |
| `add_journal_entry`——**ジャーナルエントリの下書きを作成** | `text`、任意で`task` | `drafted`、`kind` |

## 上限

スクリプトの上限は、そのマニフェストに書かれています。フォームで設定できるのは、次の3つです:

| 上限 | 既定値 | 範囲 |
|---|---|---|
| **計算時間(秒)** | 5 | 1〜30 |
| **ツールの呼び出し回数** | 20 | 0〜50 |
| **メモリ(MB)** | 32 | 8〜128 |

数えられるのは、スクリプトが計算している時間だけです。ツールにかかる時間は含まれません。上限を超えたスクリプトは終了され、どの上限だったかがダイアログに表示されます。終了したスクリプトは何も返しません。1回の呼び出しの引数と結果は、それぞれ最大64 KBです。

## 承認するまで何も実行されません

スクリプトが新しく届いたか変更された場合（同期によるもの、またはほかのプログラムが書き込んだもの）、**このデバイスで**承認するまで実行されません。そのスクリプトは、**スキル**の上部の**承認待ち**に表示されます。**確認して承認**では、**できること**、**上限**、**入力**、そして**コード**の全体を確認でき、コードがJavaScriptとして読めるかどうかも示されます。読めないコードは承認できません。

**承認**を押すと、このデバイスがまさにこれらのファイルに署名します。そのためのキーはこのデバイスで作られ、キーチェーンに保管されます。ファイルに少しでも変更があると承認は取り消され、ほかのデバイスではスクリプトがそれぞれの承認を待ちます——承認をあるデバイスから別のデバイスへ持ち運ぶことはできません。スクリプトのメニューの**承認を取り消す**を選ぶと承認が解除され、**コードを見る**を選ぶと確認の画面がもう一度表示されます。

## ベータ版の制限

スクリプトが行うのは提案と下書きだけです。ノートの名前の変更、移動、削除は行わず、メールや予定も作成しません。スキルからスクリプトを実行することはできず、スキル自身の`scripts/`フォルダーも実行されません。メール、インターネット、外部サーバーのツールは、スクリプトからは使えません。
