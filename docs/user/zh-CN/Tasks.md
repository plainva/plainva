# 任务

更新日期：2026-09-20

任务视图会把仓库中的每一个复选框汇集到一处：所有笔记中的`- [ ]`和`- [x]`列表项，会按照它们所在的笔记分组显示。这是一个基于纯Markdown、回答"我还有哪些事要做？"的视图——不需要插件，也不需要特殊文件。

## 为什么使用独立视图（而不是`.base`）

[数据库（`.base`）](Databases_Base.md)以整篇笔记为单位工作——每篇笔记对应一行。复选框只是笔记内部的一*行*文本，而一篇笔记可以包含许多个复选框，因此`.base`无法列出它们。任务视图是基于行的：它会直接读取任务所在的文本行，因此一篇包含十个子任务的项目笔记会显示全部十条。

## 打开任务视图

- 点击最左侧**操作栏**中的**清单图标**，或
- 打开**命令面板**（`Ctrl/Cmd+P`）并运行**打开任务**。

它会像任何笔记一样，以标签页形式打开。

## 在手机上

任务视图在移动端也同样存在。你可以通过顶部栏中**标题旁的▾**打开它，也可以把它放进导航栏（**设置** → **导航栏**）。

它展示与桌面版相同的两个部分：上方是**任务数据库**，下方是**来自笔记**——熟悉的复选框列表，配有**未完成**/**已完成**/**全部**筛选和自由文本搜索。勾选完成、**更改状态**、把复选框**移动到数据库**、**+ 新建任务**、**预留时间**和**重复**都和前文所述一样运作，并写入相同的文件：同一篇带有Frontmatter的笔记，原来那一行中同样的`[[内部链接]]`，以及`plainva.repeat`下同样的规则。

你的仓库使用哪个数据库作为任务数据库，这项设置在手机上位于**设置** → **内容与结构**中。该设置会随[设置同步](Sync_Setup.md)一起传递，因此你只需在任意一台设备上选择一次。

桌面版工具栏中的四个筛选项在手机上会以芯片形式显示在列表上方：**文件夹**、**标签**、**有截止日期**、**显示已隐藏**。之所以用芯片而不是下拉菜单，是因为在本已狭窄的列表上方放一条筛选栏，占用的空间会超过它带来的好处——点一下打开选择，再点一下又清除它。

## 查看列表

任务会按笔记分组；每组的标题就是笔记标题，点击即可打开该笔记。每个任务都会显示其复选框和文字内容，完成后会加上删除线。任务行中以`📅 2026-08-01`形式写出的**截止日期**会显示为一个小徽章。

## 筛选

顶部的这一栏可以缩小列表范围：

- **未完成 / 已完成 / 全部**——按复选框状态筛选（默认从**未完成**开始）。此筛选器属于**全部**列表；规划器列表**今天**、**即将到来**、**收件箱**和**已完成**本身就能回答这个问题。
- **筛选任务…**——自由文本，匹配任务文字。
- **所有文件夹**——只显示所选文件夹（及其子文件夹）中的任务。
- **所有标签**——只显示带有所选内联`#tag`的任务。
- **有截止日期**——只显示带有`📅`日期的任务。

标签和截止日期会直接从任务所在的这一行文字中读取——例如`- [ ] 支付发票 #finance 📅 2026-08-01`。

## 勾选任务

点击任务的**复选框**，即可在未完成和已完成之间切换。这个变化会直接写回笔记文件（一次普通、安全的文件写入——只有`[ ]`/`[x]`这一个字符会发生变化），因此笔记本身、Obsidian以及任何同步都会保持一致。点击任务的**文字**部分则会打开该笔记，并跳转到对应的那一行。

如果笔记在列表生成之后发生了变化，一次过期的切换操作会被跳过，并且列表会自动刷新——你也可以随时点击右上角的**刷新**按钮来重新加载。

## 默认任务数据库

复选框适合随手记一笔，但有时一行文字会逐渐成长为一项"正式"的任务——需要状态、截止日期，以及属于自己的一篇笔记。为此，可以在**设置 → 仓库 → 内容与结构**中选择一个**默认任务数据库**：一个[数据库（`.base`）](Databases_Base.md)，让这类任务以独立笔记的形式存在。**新建数据库…**会为你搭建一个现成的数据库（一个存放文件夹，加上一个带**已完成复选框列**（`done`）、状态列、截止日期列，以及表格、看板和时间线三种视图的`.base`——时间线会把每个任务放在它的截止日当天）；你也可以直接选用一个已有的数据库。复选框属性是任务的完成状态真值（开/关，与各服务商一致）；勾选后，状态列会保持一致。没有复选框列的数据库会回退到状态约定：第一个选项=未完成，最后一个选项=已完成。

设置完成后，任务视图会显示两个部分：上方是**任务数据库**中的条目，下方是**来自笔记**——也就是熟悉的复选框列表。状态可以直接在概览中修改：复选框即笔记的已完成复选框属性，点击即可切换它（状态列会随之更新），点击状态芯片则会打开一个包含所有选项的菜单（**更改状态**）。**未完成**/**已完成**/**全部**筛选适用于这两个部分，**作为数据库打开**可跳转到完整的数据库视图，包含看板和筛选条件。当已连接账户时，**刷新**还会额外触发一次真正的服务商同步。

## 把复选框变成数据库任务

每个任务都带有一个数据库图标：**移动到任务数据库**。点击一次会：

- 在数据库的存放文件夹中新建一篇笔记（如果设置了默认模板，会使用该模板）。
- 把`📅`日期填入截止日期列，为未完成任务设置第一个状态选项，并把该行的`#tags`保存为笔记的标签。
- 通过`source`属性把新笔记关联回其源笔记。
- 用一个指向新任务笔记的内部链接，替换源笔记中的复选框那一行——该条目在原处依然可读，而任务本身现在保存在数据库中。

**右键点击**该图标可以改选其他数据库作为目标；如果尚未设置默认任务数据库，点击时会直接打开这个选择器。一切都保持为纯Markdown：新任务是一篇带有Frontmatter的普通笔记，源笔记中的链接则是一个普通的`[[内部链接]]`。

章节标题中的**+ 新建任务**会将光标移到列表上方的输入框中（参见下文*规划器、快速添加、优先级与状态*）。任务会直接在任务数据库中创建——存储文件夹、模板和默认值都与移动后的复选框相同——并且通知会提供**“打开”**选项。写在笔记中的复选框仍会留在该笔记里——只有移动它们时才会变成数据库任务。

## 为任务预留时间

任务有截止日期，还可以带有**具体时间**（`2026-09-21T14:00`）——那就是 Plainva 提醒你的时刻。时间是一个时刻，而不是一段时长。想为某个任务留出一段时间时，Plainva 会创建一个**日程**——日程才是拥有时间区间的对象，会在时间网格中显示重叠情况，并与你的日历账户同步。

任务行上的日历图标会打开**预留时间**：日期（默认填入截止日期）、开始时间和**时长**（15 分钟、30 分钟、1 小时、2 小时或**自定义**）；当有多个可写日历时，还会显示日历选择。日程使用任务的标题，并链接回该笔记。 在该行上**右键点击**会显示与手机端操作面板相同的操作：完成/未完成、移到数据库、重复、预留时间。

对于数据库中的任务，笔记还会把这次预留记录在前置数据中（`plainva.blocks`），因此两端都能看到这层关联。复选框行没有自己的笔记——那里只会创建日程，并指向该行所在的笔记。只有连接了日历账户时才会出现这个图标。

## 重复任务

定期重复出现的任务，可以通过**任务数据库**部分中的重复图标来设置**重复**。Plainva 不会创建一个**系列**：勾选完成该任务后，会在已完成的任务旁新建**下一个**任务（作为独立的笔记），并带上新的截止日期。这样一来，任何时候都只有一个任务处于未完成状态，已完成的任务则作为完成记录保留下来，也没有一个隐形的系列会被你不小心整个删除——删除某个任务，这条链就此终止。

该对话框提供三项设置：

- **周期**——每天、每周、每月或每年，加上**每**后面填写的间隔数（例如"每 3" + "每天" = 每三天一次）。
- **起算于：截止日期**——固定节奏（例如"每周一"）。哪怕你很晚才勾选一个已逾期的任务，Plainva 也会跳到**未来**最近的一次截止日期，而不会把你错过的那些全部塞进列表。
- **起算于：完成日期**——周期从你勾选完成的那天开始计算（例如"每次浇花后三天"）。

**不重复**会再次移除这项设置。按月重复的任务永远不会越过月末：1月31日加一个月是2月28日或29日，而不是3月3日。

在**日历**中，重复任务因此只会出现**一次**——就在它当前的截止日期上，行上带有重复图标。这并非缺陷，而是这套生成机制的另一面：不存在一个系列，让日历可以从中画出更多次出现；而没有笔记支撑的行也无法被打开。相反，如果把重复设置在**关联的日程**上（通过**预留时间**），那才是真正的日程系列：你的服务商会将其展开，你会看到许多次出现——但这不会创建**任何任务**，只会创建日程。

这条规则保存在笔记的Frontmatter中（`plainva.repeat`），因此会随你的同步一起传输——既不是应用里隐藏的一项设置，也不是数据库的一列，因为它只属于**这一个**任务，而不属于数据库中的每一条记录。从你的服务商任务列表镜像过来的任务不提供这项重复功能：它们已经在服务商那边重复，如果再叠加一层本地周期，就会把重复出现的任务又推送回服务商那里。

## 从任务视图中隐藏笔记

有些笔记里的复选框从来都不是"真正的"任务——尤其是**模板**。为了让它们不出现在列表中，一篇笔记可以把自己排除在外。真相始终保存在文件里：这项排除设置是笔记中的一个Frontmatter字段，而不是应用里隐藏的一项设置。它会参与同步，在Obsidian中可见，也可以用任何文本编辑器查看：

```yaml
---
plainva:
  tasks: false
---
```

你不必手动写入这个字段：

- **从任务中隐藏**——每篇笔记的标题行右侧都有一个眼睛图标；点击一次即可把标记写入该笔记，并将其隐藏。
- **显示已隐藏**——筛选栏中的这个选项会把隐藏的笔记重新带回列表（呈暗淡显示），每一条都带有一个**重新在任务中显示**的图标（会移除该标记）。
- **隐藏模板**——如果你的模板文件夹中含有带复选框的笔记，右上角会出现一个**隐藏模板**按钮，一次性为它们全部打上标记。

新建的模板会自动带有该标记。当你**基于**某个模板创建笔记时，该标记会被再次移除——新笔记是真实内容，其中的任务会正常显示。

## Obsidian兼容性

任务本身是普通的GFM（GitHub-Flavored Markdown）复选框。Plainva从不添加特殊语法：同样的`- [ ]`这一行，在Obsidian中会渲染为复选框，在任何编辑器中都能干净地读取。`📅 date`和`#tag`这样的约定是Obsidian Tasks插件常用的写法，但在你的笔记里，它们不过是普通文本。

## 在总览中完成任务

在总览中勾选任务时，Plainva 会把复选框写回源笔记，并在重新查询列表之前更新该笔记的搜索索引。任务会立即从**未完成**中消失，也不会因为旧索引而再次出现。

## Tasks 元数据与重复任务

桌面、移动端和实时预览识别 ➕ 创建、✅ 完成、📅 截止、⏳ 计划、🛫 开始、🆔 ID 和 🔁 重复。日期格式为 YYYY-MM-DD。移动行后，原 ID 保持不变；未知信息仍保留在 Markdown 中。

仅自动处理英文规则 `every [N] day/week/month/year[s] [when done]`（N 为 1–999）。完成后推进一个周期，即使下一次仍已逾期；`when done` 从完成日计算。各日期间距保持不变，月底日期会限制到有效日期。无日期任务的下一项仍无日期。复杂规则、依赖、块 ID、重复 ID、无效日期、缩进内容、Plainva 原生重复及服务商任务均停用此生成器。

勾选有元数据的任务会添加完成日期。支持的重复任务会在需要时补充 ID，并给下一项分配独立的 `pv-…` ID。复选框与下一项属于同一次 Markdown 编辑，可在编辑器中一起撤销。重新打开原任务并再次勾选，会保留已有的下一项及其修改。

原生数据库任务仍跳过错过的周期。持久保存的目标计划避免重复生成。若下一项未确认，请检查任务文件夹；写入失败后，重新打开并勾选可继续原计划。源笔记已变化时不会写入不同副本；请检查笔记，必要时手动创建下一项。已确认的下一项被删除后不会恢复。

## 恢复任务筛选

状态、搜索文字、文件夹、标签、仅显示有截止日期的任务及隐藏任务的显示设置，会按仓库保存在本设备上，打开笔记或重启后仍可恢复。“重置筛选”会回到没有其他条件的未完成任务。不可用的文件夹和标签仍会显示，可通过相应选择器移除。忘记仓库会删除此视图状态。默认任务数据库仍沿用仓库设置；筛选条件不会同步。

## 规划器、快速添加、优先级与状态

任务视图默认打开**今天**。列表——桌面端是左侧的一条栏，手机端是列表上方的一个分段——分别是**今天**（今天到期的任务，**已逾期**排在最上面）、**即将到来**（未来 14 天，按天分组）、**收件箱**（没有日期的未完成任务）、**全部**（上述两部分内容，并带有**未完成**/**已完成**/**全部**筛选器）和**已完成**。每个列表都同时取自任务数据库和笔记中的复选框这两个来源，按优先级、然后按时间、然后按标题排序。其余筛选器对每个列表都生效，选定的列表会按 Vault 分别记住。在桌面端，该栏还会把最常用的标签列为一键筛选；在手机端，**今天**屏幕会进入规划器的**今天**。

列表上方是输入框；手机端的**+ 新建任务**和**＋**按钮会将它作为一个面板打开。输入一行——`明天 发送报价 14:00 !!! #客户 每周`——然后按回车：Plainva 会在任务数据库中创建该任务。它能识别今天、明天、后天、星期几、“3 天后”、“下周”、数字日期、时间（`14:30`、`2pm`）、重复规律（每天、每周、每月、每年、“每周一”、“每 2 周”）、代表低、中、高优先级的`!`、`!!`和`!!!`，以及`#标签`——文字部分使用应用所用的语言，数字和符号可以使用任何语言。所有被识别的内容都会在输入框内标出，并在保存**之前**以可移除的小方块形式列在下方；移除一个方块，它的文字就会重新算作标题的一部分。在手机端，快捷按钮会替你输入相同的文字。如果任务数据库指定了某个提供方列表，一个开关会决定该任务是否也在那里创建。

行菜单中的**设置优先级**（桌面端右键单击，手机端长按）提供**高**、**中**、**低**和**无**；标题前的旗标会显示优先级。在任务数据库中，优先级是一个选择列：现在新建的数据库自带该列，较旧的数据库会在你第一次设置优先级时获得该列——仅仅打开数据库并不会。复选框会在所在行携带 Obsidian Tasks 插件的标记：Plainva 将 🔺 和 ⏫ 读作高，🔼 读作中，🔽 和 ⏬ 读作低，并写入 ⏫、🔼 或 🔽。

`- [/]`（**进行中**）和`- [-]`（**已取消**）也是任务。它们在编辑器、阅读模式和每个列表中都有专属的复选框；进行中算作未完成，已取消算作已完成。点击仍然只在未完成和已完成之间切换——它会把进行中的任务标记完成，把已取消的任务重新打开。行菜单中的**设置状态**用来设置这两种状态；Plainva 自己不会写入它们。

还有更多创建方式：桌面端托盘菜单中的**新建任务**（当 Plainva 在后台持续运行时）、Android 上启动器的快捷方式**新建任务**（长按应用图标），以及在手机端向 Plainva 分享内容时的**创建为任务**——文字和附件会进入该任务的笔记。带时间的任务如何提醒你，在[日历与外部任务](Calendar_and_Tasks.md)中有说明。
