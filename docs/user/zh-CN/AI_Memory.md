# 记忆（测试版）

更新日期：2026-10-09

记忆保存的是AI应该了解的、关于你和你的工作的信息，这样你就不必再次告诉它：你做什么工作、你希望得到怎样的回答、你的客户是谁。记忆就是你仓库中的两个文件。没有你的同意，任何内容都不会进入记忆，而且每个条目你都可以阅读、修改和删除。

## 两个存放位置

**始终附带**中的内容会进入每一个新对话。请保持简短：它可容纳2,000个字符，并有一个进度条显示已用了多少。放不下的条目会被标为**空间已满——不会附带**：它已保存，但不会随对话发送。条目按它们的排列顺序附带，所以最重要的内容应放在最前面；要调整顺序，请在文件中修改。

**按需查阅**中的内容不会随对话发送。当某个问题可能取决于你之前告诉过AI的事情时，AI会到这里查找，对话中会显示**正在查阅记忆**。这里适合存放只在某些时候才重要的内容：某位客户的条款、一项决定及其理由。

## 打开记忆

在桌面端，在AI标签页中选择**记忆**（位于**技能**旁边）。在手机上则是**对话 → 记忆**。**设置 → AI与自动化**（仓库部分）也可以进入记忆：在**技能与记忆**下选择**打开记忆**。

## 自己添加条目

**新建条目**会询问三项内容：文字（每个条目只写一件事，单独一行，最多500个字符）、存放位置（**始终附带**或**按需查阅**），以及是否勾选**仅此设备上的模型**。凡是不该告诉任何云端模型的内容，都请勾选它。

条目的⋯按钮——在手机上是点按该条目——提供**编辑**、移到另一个存放位置（**始终附带**或**仅按需查阅**）和**删除**。

## 让AI记住某件事

在对话中说：“记住，我按天计费，而不是按小时计费。”AI会起草一个条目，但绝不会自己把它写入记忆。在它的回答下方，一张**草稿 · 记忆条目**卡片会显示完整的文字。选择存放位置，然后点击**记住**——或者点击**放弃**。你尚未决定的草稿会留在**待处理**下，记忆中会注明有多少个草稿在等待。

“忘掉……”的处理方式相同：卡片上写着**草稿 · 从记忆中移除**，**移除**会把该条目移出记忆。当你告诉AI某件事有了变化时，卡片会在**替换**下显示新的说法取代的是哪个条目。

已完成的对话也可以建议条目：**从此对话中学习**会把它再读一遍并留下草稿，每份草稿都附有依据。具体如何进行，以及这样的重读究竟可以建议什么，在[技能](AI_Skills.md)中有说明。

## 规则不是记忆

“总是用德语回答”不是一条需要了解的信息，而是一件要去做的事。这样的规则不会进入记忆：它会成为**仓库的指令**（`AGENTS.md`）中的一行，每个模型都会把它当作指令收到。可以在**给AI的规则**下用**添加规则**添加一条，也可以请AI来添加；这时卡片上写着**草稿 · 给AI的规则**，按钮是**添加为规则**。

和所有指令一样，这个文件必须在每台设备上先获得批准，才会在该设备上生效（参见[技能](AI_Skills.md)）。你在已批准该文件的设备上添加的规则，会在该设备上立即生效；你的其他设备则会先询问你。

## 整理

记忆越积越多，就会出现重复。记忆视图的**整理**部分会列出此设备自行发现的内容，无需询问模型：两个说的几乎是同一件事的条目、一个添加已超过一年的条目，以及**始终附带**中已放不下的条目。**比较**会把这两个条目放在一起显示，每个条目都附有其菜单中的全部操作。

要更仔细地查看，可以使用一个技能。**记忆维护**会用对话所用的模型读取这些条目，并拟出哪些可以合并、哪些可以删除的草稿；**让AI通读记忆**这一行会启动它。它提出的建议和其他草稿一样：在你采纳之前不会有任何改动，而且当两个条目相互矛盾时，它会提问，而不是自行决定。

## 隐私

- 条目可以带有自己的规则：**不发送给云端模型**、**不用于联网的对话**。此设备上的模型会收到每一个条目。
- 如果AI起草条目的那次对话读取过受隐私规则约束的笔记，这个条目会获得同样的规则——卡片上写着**这个条目会沿用本次对话所依据笔记的隐私规则。** 来自必须留在此设备上的笔记的内容，不会通过记忆到达云端。
- 你的[隐私规则](AI_Assistant.md)同样适用于这两个文件：为 `.agent/` 设置文件夹规则，整个记忆就不会发送到云端。
- 发送概览中有一行**记忆**，显示有多少个条目随请求发送；被你的规则保留的条目则计入**未发送**。它从不指明是哪个条目。
- 对AI来说，条目是信息，而不是指令：记忆中的一句话不会赋予AI任何权限。
- 对话会沿用开始时所带的记忆。你删除的条目不会进入任何新对话；已经开始的对话仍保留它们当时得到的内容。

## 关闭记忆

**在此设备上使用记忆**会一直开启，直到你把它关闭。关闭后，此设备上的对话既不会从记忆中获得任何内容，也不会向其中添加任何内容。文件保持原样，每台设备各自决定。

## 两个文件

`.agent/active_memory.md`（始终附带）和 `.agent/MEMORY.md`（按需查阅）都是纯Markdown文件。每个条目是一个列表项，标题用来给条目分组。Plainva对条目所知道的信息，写在它后面的一条注释中：

```markdown
## Clients

- Harbour Studio pays within 14 days.
- I bill per day, not per hour. <!-- plainva: added=2026-10-09; by=assistant; source=Offer for Harbour Studio; deny=cloud -->
```

`added` 和 `by` 说明条目是何时添加的，以及它是你自己写的还是你接受的草稿；`source` 写明草稿来自哪个对话；`deny` 保存它的规则（`cloud`、`web`）。你可以用任何编辑器编辑这些文件。在Plainva中，可用**打开文件**打开其中任意一个。

Plainva不会猜测。注释损坏的条目会被标为**规则无法读取——不会发送给任何模型**，直到你修复这条注释或重新添加该条目。隐藏在注释或不可见字符中的文本永远不会被发送；此时条目会显示有多少个隐藏的部分被略过。一个文件最多包含2,000个条目，大小最多256 KB。
