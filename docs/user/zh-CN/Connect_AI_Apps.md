# 连接AI应用（测试版）

更新日期：2026-09-30

你电脑上的AI应用——Claude Code、Claude Desktop、Cursor、VS Code以及其他支持Model Context Protocol（MCP）的应用——可以通过Plainva读取你的保险库：搜索它，读取笔记及其段落、大纲、反向链接、数据库、任务和最近的笔记，并在Plainva中打开笔记。它们不能更改任何内容。这是实验性AI功能的一部分，只在桌面端可用。

## 工作原理

Plainva在应用旁边附带一个小型辅助程序`plainva-mcp`。AI应用启动它，辅助程序再通过此电脑的私有通道连接正在运行的Plainva——在Windows上是命名管道，在macOS和Linux上是私有文件夹中的套接字。从不打开任何网络端口。Plainva必须在运行并打开了保险库；否则应用会收到明确的提示。

## 开启

1. 打开**设置 → AI与自动化**，开启**在此设备上使用AI**。
2. 开启**允许此电脑上的AI应用读取这个保险库**。
3. 设置应用（见下文）。第一次连接时，Plainva会询问这是哪个应用、由哪个程序启动，以及它可以读取哪些文件夹。默认什么都没有勾选：选择文件夹或**整个保险库**，然后点**允许**。点**拒绝**会拒绝该应用，并且Plainva在十分钟内不会再询问它。

应用会把一个密钥保存在系统钥匙串中，供下次使用。文件夹按应用和保险库分别授权：在另一个保险库中，应用会再次询问。

## 设置应用

- **Claude Code：** 从设置中复制**Claude Code的命令**，并在终端中运行。
- **Claude Desktop：** **创建安装包…**会写出一个`plainva.mcpb`文件；打开它，Claude Desktop就会安装Plainva。
- **其他应用（JSON）：** 复制配置，并添加到应用的MCP设置中，例如Cursor的`mcp.json`。

## 应用能看到什么

只有你允许的文件夹，而且只有你的隐私规则允许发送给云端模型的内容：带有`cloud: deny`的笔记，或位于带有此规则的文件夹中的笔记，对应用来说并不存在——既看不到正文，也看不到标题——；指向它们的链接会被隐去，日志中的地点从不发送。Plainva自己的文件夹（`.plainva`、`.agent`）和规则本身永远无法读取。请求和回答中的每个路径都会检查两次：在应用窗口中，以及在Plainva的原生部分中。

设置中会列出已允许的应用及其文件夹和最近的请求。**移除**会在所有保险库中收回某个应用的权限。

除了工具之外，Plainva还以应用的语言把三个技能作为提示词提供：`daily-orientation`、`weekly-review`和会询问项目名称的`project-status`。支持提示词的应用会把它们列在自己的命令中。

## 限制

- 仅限桌面端：手机上不运行这类应用，而且iOS和Android都不允许一个应用为另一个应用提供私有通道。
- 浏览器中的ChatGPT和claude.ai无法访问它：它们只能连接互联网上的服务器，而Plainva并不运行这样的服务器。
- 只读；让应用提出修改建议的功能会在以后的版本中提供。
