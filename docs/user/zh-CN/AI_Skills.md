# 技能（测试版）

更新日期：2026-10-09

技能是一组用于重复性工作的指令：准备会议、整理任务、每周回顾。Plainva自带十二个技能，你也可以编写自己的技能。技能使用开放的Agent Skills格式（一个包含 `SKILL.md` 的文件夹），因此也能在其他读取该格式的AI应用中使用。

## 使用技能

一键即可启动技能：在空白对话中点击标签（最常用的三个），在AI标签页的**技能**下，在手机上的**对话 → 技能**中，或从命令面板启动。之后对话会使用该技能：它的指令随之发送，并且只使用该技能列出的工具和文件夹。

你也可以直接提问。在每个对话中，AI都知道你已启用技能的名称和描述，并会在问题匹配时加载其中一个——说一句“为我的下一次会议做准备”就够了。

## Plainva自带的技能

| 技能 | 作用 |
|---|---|
| **今日概览** | 今天的重点：到期的任务、日程以及你最近在做的事。 |
| **每周回顾** | 过去七天和即将到来的一周，并给出三条建议。 |
| **项目状态** | 项目的目标、进展、待办事项和下一步。 |
| **会议准备** | 根据以前的笔记和未决事项准备会议，或在会后进行整理。 |
| **任务梳理** | 整理你未完成的任务：现在做什么、什么可以等、什么可以放弃。 |
| **调研** | 在网络和你的笔记中调研一个问题，并注明每个来源。 |
| **邮件和日历** | 浏览近期邮件和即将到来的日程：哪些需要回复、要准备什么、会产生哪些任务。 |
| **写作与修改** | 总结、缩短或改写笔记，作为你可以直接采用的文本。 |
| **知识维护** | 找出内容重复、已经过时或没有任何关联的笔记。 |
| **链接整理** | 检查笔记中的链接：指向不存在之处的、缺少的、单向的。 |
| **隐私检查** | 找出笔记中应留在本设备上的内容，并建议一条规则。 |
| **反思** | 和你一起回顾一天或一周的笔记——态度温和，从不做诊断。 |

它们都只读取：不会更改笔记，也不会发送任何内容。只有**调研**会使用互联网，也只有**邮件和日历**会读取你的邮件——见下文。隐私检查和反思适用于本设备上的模型；使用云端模型时，发送概览会提示这一点。你可以在**技能**中关闭任意技能——该开关对本设备上的这个仓库有效。**创建自己的版本**会把自带技能复制到你的仓库中，你可以在那里修改。

## 在互联网和你的邮件中

**调研**是Plainva自带的技能中唯一使用互联网的一个。是否启动它，是你为其对话做出的选择，就像输入框下方的地球图标：在你开启了**允许AI在此仓库中使用互联网**的地方，它会搜索并读取网页——而且只要你的笔记在对话中，每个网页和每次搜索仍会先询问，详见[AI助手](AI_Assistant.md)中的**使用互联网**。在开关关闭的地方，它只在你的笔记中调研，并会说明这一点。当AI在你未使用互联网而开始的对话中自行加载该技能时，同样如此。

**邮件和日历**通过与任何对话相同的询问来读取邮件：第一次是**读取你的邮件？**它从不亲自读取邮件正文；由第二个不带工具的读取方写出一份报告。这两点都在[AI助手](AI_Assistant.md)中有说明。

你自己的技能只有在`allowed-tools`一行列出`web_search`或`fetch_url`时才会使用互联网。**检查并批准**随后会在你批准之前显示**在你为此仓库允许的范围内使用互联网。**没有列出任何工具的技能绝不会带上互联网。

测试运行从不使用互联网，也从不询问：在本次会话中无权读取的邮件会保持未读。

## 提出修改

你自己的技能只有在`allowed-tools`一行列出相应工具时才会提出修改：`propose_edit`和`set_property`用于对笔记正文和属性的建议，`create_note`、`create_entry`、`create_task`和`add_journal_entry`用于草稿，`rename_note`、`move_note`和`delete_note`用于计划。此时**检查并批准**会逐一列出这些工具，并显示**可以提出修改建议、留下草稿并提交计划。在你采纳、创建或确认之前，仓库不会有任何改动。**没有列出任何工具的技能不会提出任何内容——你之前批准过的技能也不会因此多出什么——测试运行也不会留下任何内容。三种形式的说明见[AI助手](AI_Assistant.md)中的**提出修改**。

## 你自己的技能

**新技能**会要求填写名称、描述（AI根据描述选择技能）和指令。Plainva会把它们写入你仓库中的 `.agent/skills/<名称>/SKILL.md`，它们会像任何笔记一样随仓库同步。**编辑**会像打开笔记一样打开该文件。

**导入…**接受 `.zip` 或 `.skill` 文件形式的技能。在写入任何内容之前，Plainva会进行检查：格式中恰好有一个技能、没有离开其文件夹的路径、大小限制。它还会列出许可证、它不会运行的脚本以及它没有的工具。隐藏文件（名称以点开头）不属于技能，会被略过。

## 未经你批准，什么都不会运行

仓库中新到达或已更改的技能（通过同步、导入，或在本设备或其他设备上的编辑）在你**于此设备上**批准之前不会运行。这类技能会显示在**技能**顶部的**等待你的批准**中，以及**设置 → AI与自动化**（仓库部分）中。**检查并批准**会显示该技能可以做什么、自你上次批准以来的变化、它的指令、文件以及所在位置。批准只对这一版本有效；任何更改都会使其失效。批准保存在本设备上，从不保存在仓库中。

仓库顶层的 `AGENTS.md` 也是如此：批准后，它的常设指令会加入每个新对话。技能和 `AGENTS.md` 都不能解除你的隐私规则，技能获得的权限也永远不会超过对话本身——它只能收窄范围。 你在记忆中添加的规则，或你接受AI起草的规则，都是这个文件中的又一行；参见[记忆](AI_Memory.md)。

## 用模型测试技能

技能可以带有测试场景：一条启动它的消息，以及一次好的运行会做什么。随附的技能已经带有场景；对于你自己的技能，把它们写在技能文件夹里的 `tests/scenarios.json` 中：

```json
{
  "version": 1,
  "scenarios": [
    {
      "id": "rates",
      "message": "Check the offer against last year's rates.",
      "tools": { "required": ["read_note"], "forbidden": ["run_command"] },
      "cites": ["Offer"],
      "never": ["internal margin"]
    }
  ]
}
```

`tools` 列出好的运行会用到的工具和不得使用的工具；`cites` 是回答会提到的笔记；`never` 是回答中绝不能出现的文本。一个技能最多有八个场景。

**技能** 底部或某个技能菜单中的 **用⟨模型⟩测试**，会用新对话将使用的模型运行这些场景。不会自动开始：对话框先说明将用哪个模型运行多少个场景，由你设定以美元计的 **上限**；达到上限后，测试会在两个场景之间结束。如果模型的价格未知，测试会在固定数量的 Token 之后结束；在此设备上运行的模型不需要上限。

每个场景都是其技能的一次普通运行：它像手动运行一样读取你的仓库，经过同一份发送前的概览，计入你的用量，并把对话留在历史记录中，下一次运行会替换它。之后，每个场景都会用文字显示结果，技能所在的行会说明上次运行的情况。一个结果只针对一个模型和技能的一个版本：如果你选择了另一个模型或更改了技能，该行会说明这一点，而不是显示一个不再算数的结果。随附的部分场景询问的是 Plainva 自己的测试仓库中的笔记；它们在你的仓库中不适用，对话框会单独统计，而不会判为未通过。

## 发送给提供商的内容

发送概览会在**指令**下列出随请求发送的内容：对话的技能、AI可以加载的技能列表以及 `AGENTS.md`。当仓库中的指令首次发送到云端时，概览会再次出现。技能中的不可见字符永远不会到达模型。

## 测试版的限制

技能本身不运行脚本；关于读取你的仓库的小程序，请见[脚本](AI_Scripts.md)。你自己的技能不会提供给通过MCP服务器连接的AI应用；只有Plainva自带的技能会被提供。
