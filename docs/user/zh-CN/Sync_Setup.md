# 设置同步

更新日期：2026-10-30

Plainva可以选择性地把每个仓库与你自己选择的存储同步——直接从应用内完成，中间没有任何由Plainva运营的服务：你的数据只会在你的电脑和你自己的账户/服务器之间传输。本页逐步说明各服务商的配置方法。

哪些服务大体上可用（包括通过WebDAV或服务商的桌面客户端）在[同步兼容性](Sync_Compatibility.md)中有详细说明。

## 比较已保存的版本

文本冲突无法自动合并时，每个原文件会保留一个本地工作副本。之后的编辑会保存到同一个副本中，重新打开笔记或重启应用后也是如此。提示栏会说明：**你正在编辑冲突副本。合并后才会同步。**

在比较界面中，**比较已保存的版本** 可显示已保存的初始版本（如果有）。工作副本在本次会话之外被修改时，另一个版本也会保留，并可在此比较。采用副本、保留两者和丢弃副本都会重新检查当前文件；比较内容已过期时，请重新加载。移动或删除相关文件及其文件夹之前，请先解决冲突。旧的冲突副本仍会单独列出。

冲突未解决期间，应用的其他部分仍会继续使用这条笔记。在编辑器之外所做的更改——数据库中的单元格、勾选的任务、日志条目、随笔记重命名而更新的链接——会同时写入笔记和你的冲突副本，因此无论保留哪个版本，更改都在。如果你的副本中已没有该更改对应的位置（例如你在那里改写了某个任务的文字），副本会保持原样，比较界面会显示这一差异。如果在你的设备上传之前，另一台设备修改了笔记本身的同一处，笔记自己的文本也不会丢失：它会作为另一份冲突副本保存在笔记旁边。

诊断导出还包括最近的冲突记录：存储类型、写入来源、哈希比较，以及换行符、BOM 或末尾换行的差异。这些冲突记录不包含笔记内容或文件名。无论应用使用哪种语言，诊断导出始终为英文，方便你原样粘贴到 GitHub 的 issue 中。

## 基础知识

- 配置入口在**设置 → 仓库 → 云账户**：**连接账户…** 会打开助手。它对每个服务商都是同一个，在电脑和手机上一样，分五个步骤：**服务商** › **服务** › **登录** › **设置** › **完成**。在**服务**步骤中（用于文件同步的是**文件**），始终列出全部三项服务——**文件**、**日历与任务**和**邮件**；服务商无法承担的服务，列表中会以关闭状态显示并附上原因。**登录**步骤对每个服务商看起来都一样：顶部是所选的服务以及一行说明登录如何进行；下方是该服务商所需的内容；**其他登录方式**始终位于同一位置。之后每项服务各自报告结果——其中一项失败时，其余的继续运行，提示会说明是谁拒绝了：设备、服务商、网络或 Plainva。图块概览会按实际普及程度列出各服务商；通过**搜索服务商…** 还能找到以预设形式提供的邮件服务商。每个仓库始终恰好由**一个**账户承担**文件**服务。**同步**区域随后会显示已连接的账户，并保管适用于整个仓库的内容（**所有设备上的账户**、队列、诊断）；**此账户的云端文件夹和间隔**会进入账户的**文件**页面，那里有**云端文件夹**、**同步间隔（秒）**、同步状态和**暂停同步**。 一旦连接了 **文件** 服务，助手就会询问一次 **云文件夹**——对每个提供商都是如此，并可在选择器中直接 **新建文件夹**；**浏览** 仍然可以回到这里。WebDAV 的文件夹是服务器地址的一部分，因此那里没有选择器。
- 对于**文件**服务，除了**Microsoft**（OneDrive）、**Google**（Drive）、**Dropbox**、**Nextcloud**、**对象存储 (S3)** 以及通用的**WebDAV / CalDAV**之外，图块中还包含**Fastmail**、**mailbox.org**、**Yandex**、**Mail.ru**、**Koofr**和**pCloud**：在这些服务中，只需你的邮箱地址加上服务商所要求的访问凭据——通常是**应用专用密码**，mailbox.org 和 pCloud 则是普通的**密码**；服务器地址已经预填好（基于WebDAV；在**其他登录方式**下通过**分别设置端点**更改）。这些字段对所有已选服务只有一个表单，在手机上也是如此。
- **从欢迎界面设置已有的在线仓库**：**打开仓库** → **在线仓库**会打开与设置中相同的助手：带搜索的服务商图块（每个能承载文件的服务商，也包括Fastmail、mailbox.org、Yandex、Mail.ru、Koofr、pCloud和Nextcloud），然后是**登录**，接着是云端文件夹（**选择文件夹…**；也可以在此处通过**新建文件夹**新建一个），最后是**选择本地文件夹并打开**。你也可以随时在设置中为已经打开的仓库配置同步。 对于 Google、Microsoft 和 Dropbox，**登录**使用 **此设备的登录方式**（与 **云账户** 中的相同）登录，仓库会立即在那里获得自己的账户。
- **在云端新建仓库**：**新建仓库** → **在在线服务中**——先选择起始结构（空白或PARA等模板），然后在同一个助手中选择服务商、登录，并选择云端的目标文件夹，或通过**新建文件夹**新建一个，最后选择本地文件夹。结构会创建在本地文件夹中，并在首次同步时自动上传。
- 本地保存会立即上传；Plainva会按配置的**同步间隔（秒）** 检查远端更改。
- 离线时的更改会排入队列，等到下次联通时传输；状态栏会显示**在线**/**离线**，同步指示器会显示当前状态（点击可**立即同步**）。在长时间同步或首次同步期间，状态栏会以计数形式显示进度（例如**同步 123/540**），让你能看到它正在逐步处理整个仓库。
- 如果两端都修改了同一个文件，Plainva会自动合并（三方合并）。如果无法合并，你的版本会被安全地保存为一个`.CONFLICT`文件——任何内容都不会丢失（参见[常见问题与故障排查](FAQ.md)）。
- **解决冲突**：受影响笔记中的一条横幅（以及文件树中`.CONFLICT`文件右键菜单里的**解决冲突…**）会打开对比对话框——左侧是文件的当前状态，右侧是你被保留下来的版本，可编辑，并支持按块单独采用。**保存右侧版本并解决**会把结果写入文件并清理冲突副本；**保留另一端**则会丢弃你的副本（仍会保留一个版本快照）。同步错误对话框也会列出现有的冲突副本，点击一下即可进入同一个对比界面。
- **连接到已有笔记的文件夹**：新仓库的起始结构（其模板笔记和生成的列表，只要你没有修改过）留在本设备上，不会进入该文件夹；在手机上，为该文件夹新建的仓库不包含它。你修改过的笔记属于你，会像其他笔记一样同步。连接到新的空文件夹的仓库会上传全部内容，包括起始结构。本设备与云端对同一文件内容不同时，首次同步会保留两个版本，并用一行提示：**首次同步在本设备与云端内容不同的地方保留了两个版本：…** — **显示** 会打开第一个副本。服务商不提供的文件（Google Drive：被其标记的文件）会被跳过，并在同步状态中列出，直到可以下载；Plainva 会自行再次请求，且不会在其上上传任何内容——你在该名称下的文件会改为以 `Name (conflict …).md` 上传。
- **批量删除保护**：如果异常多的已同步文件即将在云端被一次性删除（例如因为本地仓库文件夹被清空或移动），Plainva会先暂停这些删除并询问：**在云端删除**会执行删除，**不删除（恢复）** 会放弃删除，并在下次同步时从云端恢复这些文件。你在 Plainva 中自行确认的删除不会被拦截——对于大量删除（超过 10 个文件或超过仓库的 20%），Plainva 会在删除前再次向你确认。
- **云端已删除、此处已更改**：如果另一台设备在云端删除了一个文件，而本设备上该文件仍有尚未上传的更改，Plainva 不会删除它。它会保留该文件，作为新文件重新上传，并告诉你一次是哪个文件。如果确实要删除，请在此处再次删除。桌面端和移动端均适用。
- 附件（图片等）也会一并同步。
- **空文件夹**也会同步：在Plainva中新建的文件夹会立刻出现在云端，云端已有的空文件夹最晚会在你其他设备的下一次完整同步中出现。
- 凭据和令牌保存在操作系统的钥匙串中（状态查看：**设置 → 应用 → 关于与诊断 → 系统钥匙串**），绝不会保存在仓库内的文件中。
- **已保存的凭据**（**设置 → 应用 → 关于与诊断**，**钥匙串**分组）显示 Plainva 存入钥匙串的内容，包括早已不再打开的仓库留下的条目。每一行都注明服务和仓库；**删除**会先询问。Plainva 从不在此自行删除任何内容。
- 钥匙串中的条目使用**可读的名称** —— `plainva · <仓库> · <服务> · <账户 ID> · #<指纹>`，而不是一串 base64。首次打开仓库时，Plainva 会为已有条目重命名一次；如果重命名无法安全完成，旧条目会保留原样，Plainva 会在下次打开时再试。
- **暂停同步**（在账户的**文件**页面上）会停止该仓库在此设备上的同步；此操作不会删除任何地方的任何文件，重新开启后会从停下的地方继续。在手机上，**暂停同步**位于**同步**页面的末尾，在**危险操作**分组中。
- **允许使用`http://`，推荐使用`https://`。** 在自己的网络中运行的服务器通常使用未加密的`http`——这样可行，在手机上也一样。但在互联网上不应该这样做：WebDAV会在**每次**请求时都以明文通过`http`发送你的密码。如果你在自己的网络之外输入未加密的地址，Plainva会在表单中提示——但并不会阻止你。

## WebDAV / Nextcloud

对于自建服务器和大多数云存储来说，这是最简单的方式：

1. 在**云账户** → **连接账户…** 中选择**Nextcloud**（或**WebDAV / CalDAV**）图块——在手机上，Nextcloud 是服务商列表中的独立条目——并勾选所需的服务。
2. 对于 Nextcloud，输入**服务器地址**、**用户名**和**密码**；对于 **WebDAV / CalDAV**，不是一个地址，而是**文件（WebDAV）** 和**日历（CalDAV）** 两个地址，再加**用户名**和**密码**。只要可能，就使用应用密码而不是主密码（在Nextcloud中：设置 → 安全 → 应用密码）——该步骤会提示：“在 ... 创建后粘贴到这里。”，并带有**打开 … 指南**。
3. **使用密码连接**会验证凭据；之后通过**选择文件夹…** 选择**云端文件夹**。 这里同样可以创建 **新文件夹**——凡是 Plainva 选择云文件夹的地方都可以，手机上的 **更改云文件夹** 也是如此。

**Nextcloud**的特殊之处：一个表单即可同时覆盖文件**和**日历——Plainva会直接从服务器地址推导出WebDAV和CalDAV端点（推导出的地址会显示在助手中；在**其他登录方式**下，**分别设置端点**可以设置独立的URL）。同时勾选两项服务，一次连接即可同时完成两者。

**一个表单适用于所有服务。** 所有使用凭据的服务商——Apple iCloud、Yahoo、AOL、Zoho、Fastmail、mailbox.org、Yandex、Mail.ru、Koofr、pCloud、Nextcloud、**WebDAV / CalDAV** 和 **邮件服务器 (IMAP)**——都在一个表单中为所有已选服务询问凭据，在电脑和手机上一样；以前手机按服务分别询问。凭据的名称与服务商的叫法一致：只有服务商要求时才叫**应用专用密码**（按钮**使用应用专用密码连接**）；mailbox.org 和 pCloud 使用普通的**密码**（**使用密码连接**）；一些 IMAP 服务商要求**授权码**（**使用授权码连接**）或**邮箱密码**（**使用邮箱密码连接**）。凭据需要先创建时，会有一个可见的步骤——“在 ... 创建后粘贴到这里。”——并带有**打开 … 指南**。服务器地址保持折叠在**其他登录方式**下（**分别设置端点**，IMAP 则是**分别设置服务器**）。账户页面上用于新凭据的字段与凭据同名：**新的应用专用密码**、**新密码**或**新的私密密钥**。对于设备账户**此设备上**（仅手机），则是一句话和按钮**允许访问**。

**在手机上。** 服务商列表带有搜索和步骤条；登录按钮对每个服务商都位于服务页面上（Dropbox 不再藏在文件夹步骤里）；对于使用凭据的服务商，接下来是带有那一个表单的登录页。个别服务失败时，像**不包含日历与任务继续**这样的按钮（带有受影响服务的名称）会在不包含它们的情况下继续设置。只有在登录确实发生之后，才会出现**已登录**。

常见的服务器地址（Nextcloud、Koofr、MagentaCLOUD、Storage Box等等）列在[同步兼容性](Sync_Compatibility.md)中。

**该地址指向仓库文件夹本身。** 其下的所有内容都属于该仓库，因此地址若高出一级，相邻的文件夹也会被一并纳入。在 WebDAV 中，文件夹是服务器地址的一部分——以后要移动仓库，请重新连接账户。

更改密码时，会先向所有相关的密码保护服务进行验证。如果保存中断，已确认的更改会保留。重新打开账户并选择**继续保存**。重启后，受保护的操作仍然可用。如果账户关联或凭据发生变化，可以选择**重新验证密码**，为当前关联的服务验证现用密码。缺失的凭据不会被跳过。之前关闭的 vault 下次打开时，也会使用新的日历登录。

新的日历连接始终关联到开始连接时的 vault。如果在验证期间关闭或切换该 vault，请回到原 vault 重新连接。如果无法读取现有凭据，账户合并会停止，并保留原有账户。

## Google Drive

Google Drive通过**此设备的登录方式**登录。默认是**标准登录**：如果你的版本包含它，你无需输入任何内容。如果不包含，Plainva会告知你，并请你提供**自有客户端 ID**——来自你自己的免费Google Cloud项目的客户端的ID，该项目只属于你自己（"Bring Your Own"）。分步指南见：[Google Drive（BYO）](Google_Drive_BYO_Guide.md)。

简要版本：在**云账户** → **连接账户…** 中选择**Google**图块，勾选**文件**服务，然后点击**使用 Google 登录…** ——登录界面会在浏览器中打开。若使用自有客户端 ID，请先在向导的**其他登录方式**下填写：桌面版填写“桌面应用”类型客户端的**客户端ID**和**客户端密钥**，手机上只填写“iOS”类型客户端的**客户端ID**。连接成功后，你可以通过**选择文件夹…** 直接从你的Drive中选择**云端文件夹**（包括子文件夹，默认为"Plainva"）。注意：只要你自己的Google项目处于**测试**模式，登录就会在**7天**后过期——而且是永久性的，因为Google在这种模式下也会让刷新令牌一并失效，Plainva便无法在后台自动为你续期。这时同步功能会提示你登录已过期，在账户详情中点击**重新登录**即可恢复——一次操作即可恢复该账户的**所有**服务。**已发布**状态会取消测试模式的固定有效期，但不保证永久登录：Google仍可能使访问权限过期或撤销访问权限。发布和验证要求取决于用途及所请求的权限。[Google：刷新令牌过期](https://developers.google.com/identity/protocols/oauth2#expiration)。

如果连接时同时勾选**文件**和**日历与任务**，Google 只会请求一次授权，且仅申请所选服务对应的权限。以后再添加其他服务时，会再请求一次授权，涵盖该账户已有的全部内容以及新增的服务。

## OneDrive

Plainva为Microsoft自带了登录方式（**标准登录**）——你**不需要自己的ID**：

1. 在**云账户** → **连接账户…** 中选择**Microsoft**图块，并勾选**文件**服务（OneDrive）——如果需要，可以同时勾选**日历与任务**和**邮件**（一个Microsoft账户可以同时承担全部三项服务）。
2. 点击**使用 Microsoft 登录…**，并在浏览器中确认登录。完成——Plainva会创建该文件夹（默认为"Plainva"），并同步其全部内容，包括外部添加的文件。
3. 可选：连接成功后，你可以通过**选择文件夹…** 直接从你的OneDrive中选择**云端文件夹**（包括子文件夹）。

可选：在**此设备的登录方式** → **更改** → **自有客户端 ID**下，你可以改为填入自己应用注册的应用程序（客户端）ID（例如遇到公司限制时）——仅适用于此设备。详细指南：[OneDrive与Dropbox（BYO）](OneDrive_and_Dropbox_BYO_Guide.md)。

**所有服务一次登录。** 对于**Microsoft**和**Google**，连接账户、在该账户上开启另一项服务以及**重新登录**是同一个步骤：服务商只会请求**一次**授权，涵盖该账户已有的全部内容以及你新增的服务，Plainva 会为整个账户保存一份登录。之后每项服务各自显示结果——正常，或者在你于服务商的授权界面取消了某项服务的勾选时显示**未允许——登录时未勾选。请重新登录并勾选该服务。** 重新登录并勾选它即可解决。某项服务失败不会拖累其他服务。如果你连接的账户该仓库已经有了，Plainva 会把这些服务加入该账户，而不是创建第二个账户，并会告知你。向导的**登录**步骤只显示该服务商为所选服务所需的内容：Google 和 Microsoft 各有一个按钮，即**使用 Google 登录…** 或**使用 Microsoft 登录…**，采用标准登录；你自己的客户端 ID——对 Google 来说，仅在选择了**邮件**时还有**通过应用专用密码收发邮件**——折叠在**其他登录方式**下。对于邮箱，一旦地址指向已知服务商，服务器设置就位于**其他登录方式**下；对于 Dropbox，自有的 App Key 也在那里，与 Google 和 Microsoft 用的是同一个编辑器。用与所显示账户不同的账户**重新登录**会被拒绝，且不会有任何更改。

向导会把你选定的服务商**带到每一步**：第 2 步和第 3 步直接打开对应的表单（Google 日历表单而不是服务商选择，Gmail 而不是通用的 IMAP 表单），不会再问一次你想连接谁。前一步已经收集到的内容，下一步就已经在那里：对 Nextcloud，Plainva 会从第 1 步的服务器地址推导出 CalDAV 地址；套件密码只需输入一次，而不是三次。这些内容只在本次流程期间保存在内存中，不会写到任何地方，流程结束后即消失——包括你通过**停止**中止它的时候。

沿用早期版本、仍按服务分别保存登录的账户会在其页面上注明这一点。**重新登录**会涵盖该账户的所有服务——桌面版和[移动应用](Mobile_App.md)里都是如此：只需一次操作，之后所有服务就会共用同一个登录。这不仅仅是方便：分开的登录可能会逐渐脱节，导致一项服务仍在正常运行，而同一账户的另一项服务却已悄悄过期。

**Google 账户上的 Gmail。** 当此设备的登录方式允许邮件时，Gmail 属于同一次授权，邮箱会绑定到该 Google 账户。若不允许——即没有 Google 邮件审批的 **标准登录**——在 Google 账户上开启**邮件**时，会当场要求输入**应用专用密码**，位于该账户页面的**此设备上的访问**中：仍在同一个账户下，绝不会作为第二个账户。重新登录 Google 会保留这样的应用专用密码。即使多个仓库中存在相同的账户配置，Outlook 也会按仓库分别保存登录信息和管理连接。桌面端和移动端均如此。

文件、日历和 Outlook 邮件各自需要相应权限。因此，文件同步正常并不代表日历或邮箱也已获得授权。Plainva 会检查每项服务的权限；若缺少权限，请重新登录并授予所需访问权限。Google 的等效权限名称也会被识别。

**此设备的登录方式。** 设备以哪种方式登录 Google、Microsoft 或 Dropbox，是按设备设置的，而不是整个账户——其他设备保留各自的设置。你可以在账户页面查看和更改（桌面版：**设置 → 仓库 → 云账户** → 该账户 → **此设备的登录方式** → **更改**；手机：**云账户**中的该账户 → **此设备的登录方式**一行），也可以在向导的**其他登录方式**下操作。只要你的版本包含 **标准登录**，它就是默认值，此时你无需输入任何内容。**自有客户端 ID**对 Google 桌面版需要“桌面应用”类型客户端的**客户端ID**和**客户端密钥**；手机（Android 和 iPhone）需要 Bundle ID 为 `com.plainva.app` 的“iOS”类型客户端的**客户端ID**，没有密钥；对 Microsoft 则是你应用注册的应用程序（客户端）ID；对 Dropbox 则选择**自己的 App Key** 代替客户端 ID，并填入你的 Dropbox 应用的 App Key。如果你的版本没有 Google 的标准登录，Plainva 会告知你并请你填写自己的客户端 ID。重新登录使用此设备的设置。 这一行会说明此设备用什么方式登录：**标准登录**，或**自有客户端 ID** 加上客户端 ID 的最后六个字符，例如“(…a1b2c3)”。

**检查连接。** 每个账户页面都提供**检查连接**——桌面版是对话框，手机上是底部面板。每项服务会读取一点点内容，并显示**正常**、**未登录**、**登录已过期 – 请重新登录**、**未授权 – 请重新登录并勾选该服务**或用文字写明的错误信息。每一行出错的服务都带有对应操作：**登录**、**重新登录**（对于使用密码的账户，会打开密码输入）或**授予权限**。当 Google 拒绝 Gmail 时——权限未授予、应用未通过验证，或项目达到用户上限——邮件那一行还会提供**使用应用专用密码连接**：Gmail 随即在同一账户上通过 IMAP 使用应用专用密码，被拒绝的邮箱由它取代。如果提供商拒绝此设备自有的客户端 ID，因为它已被删除或未获允许，该行会说明这一点，并在你的版本包含标准登录时提供**使用标准登录**。结果会记录到诊断信息中。

**需要登录、退出登录、移除。** Google 或 Microsoft 账户会在列表和账户页面中显示它在此设备上唯一一份登录的状态。**需要登录**表示此设备尚未为该账户登录，旁边是**登录**。**登录已失效**表示登录不再有效，旁边是**重新登录**。**在此设备上退出登录**会删除此设备的登录——对使用密码的账户，则是保存在此处的密码——账户、其服务和设置保留，其他设备仍保持登录，提供商处不会撤销任何内容；之后账户显示**需要登录**，点击**登录**会再次要求输入密码。**移除账户…** 会在确认后，把账户连同其所有服务从仓库中移除，所有设备上都生效——确认提示会说明哪些会被移除（此账户的服务、所有设备上的登录、其日历缓存）和哪些会保留（所有笔记，包括已归档的邮件和日程笔记；提供商处不会删除任何内容）。仓库及其笔记保留。如果承载仓库文件的账户在此设备上已退出登录，仓库在这里不会同步，同步状态会说明: **需要登录** ，以及通往该账户的 **登录** 。移除后再次连接到同一个文件夹，仓库会从停下的地方继续，并发送等待中的内容；连接到另一个文件夹时，它从自己的文件开始，不会发送任何原本给旧文件夹的内容。

**账户页面。** 每个账户——Google、Microsoft、Dropbox、iCloud、Nextcloud/WebDAV、S3、邮箱或**此设备上**——在桌面版和手机上都有同样的页面、同样的顺序：（1）**页头**，显示账户唯一的状态——**已连接**、**需要登录**或**已失效**——并且仅在需要时才有按钮**登录**或**重新登录**；（2）**服务**——**文件**、**日历与任务**和**邮件**，每项带一个开关、一行状态和一个通向此账户该服务页面的箭头；（3）**此设备上的访问**——Google 和 Microsoft 的登录、Dropbox 的 App Key、使用密码的账户的服务器、用户和密码、S3 的密钥、**此设备上**的系统权限；（4）**检查连接**；（5）仅当同一服务商存在第二张卡片时，才会出现折叠的**高级**组，其中的**同一个账户**用于把另一张卡片合并到这一张——前提是确定它们是同一个账户；（6）末尾的**在此设备上退出登录**和**移除账户…**。Gmail 的应用专用密码位于**此设备上的访问**中，对应**应用专用密码**这一行，不再单独成组。服务商做不到的事不会出现，也绝不会被挪到别处。关闭的开关会让该服务对仓库在所有设备上停止；连接、日历缓存和已归档的邮件保留，重新开启后会从停下的地方继续。

**账户的服务页面。** 服务旁边的箭头会打开属于此账户的内容：对于**文件**，是**云端文件夹**、**同步间隔（秒）**、同步状态和**暂停同步**（仅此设备）；对于**日历与任务**，是账户的日历和任务列表及其开关、日历自己的颜色（只为此仓库着色；服务商保留它自己的颜色）以及一个标记，表明此账户的哪个日历是默认日历（日历下方的那一行写着**默认日历**）；默认日历只在**日历**页面中选择；对于**邮件**，是文件夹、发件人和签名。每个页面都通向所有账户共用的设置：你的仓库下的**同步**、**日历**和**邮件**保管适用于所有账户的内容——提醒、会议文件夹、规则、外出回复、归档文件夹。仓库的文件关闭期间，任何设备都不同步笔记；设置仍会同步，因此重新打开文件以及期间切换的日历或邮箱都会传达到每台设备。使用 **暂停同步** 或已退出登录的设备则完全停止。

## Dropbox

Plainva自带了Dropbox应用——**无需自己的应用**：

1. 在**云账户** → **连接账户…** 中选择**Dropbox**图块（它只承担**文件**服务）。
2. 点击**使用 Dropbox 登录…**，并在浏览器中确认。完成（默认文件夹为`/Plainva`）。
3. 可选：连接成功后，你可以通过**选择文件夹…** 直接从你的Dropbox中选择**云端文件夹**（包括子文件夹）。

可选：在**其他登录方式**下会打开与 Google 和 Microsoft 相同的编辑器，其中有**标准登录**和**自己的 App Key**；你可以在那里填入一个自行注册的App key。它适用于此设备，就像 Google 和 Microsoft 的客户端 ID 一样——其他设备保留各自的设置；账户以前已有的 App Key 会被自动沿用。之后你可以在账户页面的**此设备上的访问** → **此设备的登录方式** → **更改**下修改它；旧的**使用你自己的应用 ID**字段已不复存在。Dropbox 的账户页面还会显示它的状态，在电脑上还有**在此设备上退出登录**。详细指南：[OneDrive与Dropbox（BYO）](OneDrive_and_Dropbox_BYO_Guide.md)。

## S3兼容存储

适用于AWS S3、Cloudflare R2、Backblaze B2、MinIO、Wasabi、Hetzner等等——纯密钥方式，完全不需要浏览器登录。在**云账户** → **连接账户…** 中选择**对象存储 (S3)** 图块并填写以下字段；**区域**、**Key前缀（可选）** 和**路径样式URL**折叠在**高级**下：

| 字段 | 含义 |
|---|---|
| **Endpoint** | S3 API的基础URL，例如`https://s3.eu-central-1.amazonaws.com`、`https://<account>.r2.cloudflarestorage.com`，或本地MinIO的`http://127.0.0.1:9000` |
| **存储桶** | 存储桶名称 |
| **访问密钥** / **私密密钥** | 来自服务商的一对API密钥 |
| **区域**（在**高级**下） | SigV4区域；大多数非AWS存储使用`us-east-1`即可，Cloudflare R2使用`auto` |
| **Key前缀（可选）**（在**高级**下） | 仓库在存储桶内所处的子文件夹；留空=存储桶根目录 |
| **路径样式URL**（在**高级**下） | 推荐启用（适用于MinIO、R2和大多数兼容存储）；仅在virtual-hosted风格的AWS存储桶上关闭 |

**Key前缀**（即云端文件夹）可以在连接后通过**选择文件夹…** 直接从存储桶中选择。

**连接**后，同步会立即开始。如果私密密钥发生变化，请在账户页面的**新的私密密钥**字段中填入。

## 同步加密（密码短语）

> **已在P3替换：** 以下说明不再用于仓库内容。请使用[安全与共享](Security_and_Sharing.md)。此处保留的口令仅保护可选设置与机密信息。

Plainva 可以对从你的设备发往同步服务器的内容进行加密，而你的本地仓库始终保持为Obsidian可以读取的纯Markdown格式。

打开**设置 → 仓库 → 同步 → 所有设备上的账户**：

1. **设置密码短语。** 这会为仓库创建一个加密密钥，并显示一次性的**恢复代码**——请妥善保存；如果你忘记了密码短语，这是唯一能找回访问权限的方法。从此以后，该仓库同步的**设置**会以加密形式传输。
2. **加密仓库内容**（可选）。**加密**按钮会把每一篇笔记以密文形式重新上传到同步服务器。你的本地文件仍然是纯Markdown，所以本地仓库永远不会有风险——建议先在一个可丢弃的仓库上试一试。上传完成后，使用**完成迁移**，此后就只接受密文。
3. **在另一台设备上**，打开同一个已同步的仓库。Plainva会检测到该仓库已加密，并提示你输入密码短语（或恢复代码）。解锁后，笔记会被解密并出现在本地。

已解锁的密钥会在每台设备上缓存。开启**每次启动都询问密码短语**，可以改为在每次重启后重新输入；使用**锁定**可以从此设备上移除缓存的密钥。

**所有设备上的账户**是三个步骤。**1 · 设置与账户**：把仓库设置*以及你的账户*（日历、邮箱、日历选择）存为仓库中的一个小文件——只要尚未设置密码短语，这就**不**需要；一旦设置了密码短语，每台设备都必须输入它，设置才会从该设备同步出去。此步骤**默认开启**——设置与账户并非机密；你可以随时按仓库关闭它。**2 · 同步密码短语**（可选）：只有当登录信息也需要一并同步时才需要，它还会加密第 1 步中的设置。**3 · 一并带上登录信息**：另外以加密方式携带静态的 IMAP 和 CalDAV 密码，并且只有在第 1 步已经运行且密码短语已解锁的情况下才能开启——密码只能同步到设备已知的账户。不会携带：设备专有路径和 OAuth 登录（Microsoft、Google）；它们的令牌绑定单台设备，因此账户会出现在新设备上，并需要在那里**登录**一次。

在**手机**上，你会在**同步** → **所有设备上的账户**下找到同样的链条，该行会写明它的状态——同样的三个步骤和同样的锁定。来自其他设备的账户会在那里创建，你不再需要手动输入。使用**立即从其他设备获取**可以马上取回，而无需等待下一次同步。

如果 Plainva 提示“**旧版本仍在发布已停用的账户数据**”，请在使用此仓库的所有设备上更新 Plainva。当前设备会忽略旧的 Google 客户端凭据，并保留正常工作的本地登录。所有参与同步的设备完成更新之前，请勿确认删除旧的远程数据。 相应的按钮位于**设置 → 仓库 → 同步 → 诊断**中的提示里：**删除已停用的条目**——它询问的正是这项确认。

这一步 **登录** 在哪里进行取决于服务：邮箱会在 **邮件** 区域自己那一行显示 **登录** 按钮，日历或文件账户则在 **云账户** 中显示。Microsoft 邮箱始终转到 **云账户**，因为它的登录在浏览器中进行。

**首次** 设置加密时，第 3 步默认开启——否则后续每台设备都会长期没有登录信息。对于你已经在用的保险库，不会悄悄改变：Plainva 只问一次，并记住你的回答。

如果一个账户显示为 **两张卡片**，说明 Plainva 无法从服务商获取身份——它不会猜测。在 **云账户** 中打开其中一张，用 **合并** 说明这是同一个账户；Plainva 会先显示哪些内容会被保留。

如果**日历与账户**中列出了同一个日历的两行，Plainva 会提示这一情况，但**不会**自行合并它们：合并会导致日历选择以及与镜像任务的关联丢失。请检查哪一行保留着你的选择，删除另一行。

你移除的账户会保持移除状态：这项删除会通过设置同步传递到你的其他设备，而不会在下一轮同步时从那里被重新带回来。

手机端携带的内容稍微少一些：四个**桌面端**栏位的布局留在电脑上——它自己的导航栏确实会跟随，会议文件夹也是如此。**同步**下它自己的三步链会显示它携带了什么，两端都会在**诊断**分组中说明同步最近究竟做了什么，并列出随之传输的设置项名称；接收时还会列出发生变化的项。「已从其他设备接收设置」的提示每次会话最多出现一次，且只在确有变化时出现；之后由这几行说明。 本版本起，手机端也会沿用日记的文件名格式、新笔记的 OKF 类型以及你的书签——此前，只要手机接触过设置了其他日期格式的仓库，同一天就会多出第二篇日记。

诊断现在会分别显示**最近检查**（本地配置字段）、**最近下载**、**最近应用**和**最近实际发送**。“发送”只会在成功写入云端后更新；因此，无变化的同步会更新检查与下载时间，但不会更新发送时间。密钥结果会单独显示为已导入、未更改、已拒绝、已过时、出错或等待账户的数量。这里只保存稳定的原因代码，不包含账户 ID、密码、令牌或原始错误。出现旧客户端提示时，应更新所有参与设备上的 Plainva；本设备会忽略已停用的 Google 客户端数据。

**删除会随同步传播。** 你确认过的删除会在日志（`.plainva/sync/deletions.json`）中保留 90 天，并在其他所有设备上无需询问地执行——重启后也是如此，即使那里一次缺少许多文件也一样。反之，如果云端缺少许多文件而日志无法解释，Plainva 会暂停镜像并询问：**应用删除** 还是 **保留在本地**（然后会把这些文件作为新文件重新上传）。任务列表同理：在提供商处执行的删除也会在另一台设备上移除任务笔记，前提是那里没有改动它。在询问之前——也在移除此处任何一个文件之前——Plainva 会直接向云端核实：抽取一部分缺失的文件，逐个询问。只要其中有一个存在，就说明云端的列表不完整：不会删除任何文件，也不会询问任何人，同步状态会显示 **云端的响应不完整——没有删除任何文件** 和 **重新检查**。只有在确认文件确实不存在并已在此处移除之后，才会写入日志记录；如果某条记录对应的文件又出现在云端，该记录会被撤回；**同步**下**诊断**分组中的 **检查删除日志** 可以随时执行这项检查（手机上位于**诊断**屏幕）。如果找不到一个已经同步过的仓库在云端的文件夹，Plainva 不再新建一个空文件夹来代替，而是给出提示——这时请选择现有的文件夹。

## 错误和自动重试

同步错误窗口会保留失败尝试的确切信息，即使自动重试已经改变了实时状态。它会显示重试正在进行或已经成功。只有身份验证错误才会建议重新连接；网络、超时和提供商错误会保留具体原因并自动重试。 设置同步同样会等待临时性故障：超时先显示为带计数的普通提示，只有连续第三次失败后才变成红色消息；而登录已过期时会立即变红。

## 仅拼写不同的文件名

Google Drive 在搜索时不区分大小写，Windows 和 macOS 也会把 `Note.md` 和 `note.md` 存为同一个文件。同一个字符还可能有两种保存方式：`ü` 作为单个字符，或作为 `u` 加上一个变音符号。对于这种**写法**，Plainva 现在会认定它们是同一个文件并照常同步，只要匹配项只有一个。

但如果两个名称只在**大小写**上不同，那就是两个文件。此时 Plainva 不会更改也不会删除任何内容，而是显示卡片**两种写法，同一个文件**并列出两个名称——手机上在**同步**页面，桌面版在同步设置中。其余文件继续正常同步。重命名其中一条笔记，卡片就会自动消失。

新登录未涵盖所有服务。已保留你的原有登录信息。请重新登录并允许列出的所有服务。 账户关联已更改。请打开当前账户设置并重新登录。

## Google Drive：尚未完成的下载

当 Google Drive 暂时限制请求时，Plainva 会间隔一段时间后重试下载。下载失败不会被视为文件不存在或更改已完成。现有本地内容和已确认的同步状态会保留，下一轮同步将重试尚未完成的更改。其他已成功下载的文件仍可使用。权限不足或其他持续拒绝会显示为错误，并注明文件路径和原因。桌面端和移动端均采用此行为。

## 文件传输中断

超时限制也适用于从 WebDAV、Dropbox、OneDrive、S3 和 Google Drive 接收文件内容。如果分块接收的响应不再提供数据，Plainva 会结束该次尝试，并使用新请求进行有限次数的读取重试。只要数据持续到达，即使接收整个文件超过基础时限，该下载也会继续。移动端原生请求还有各自的时间限制。不完整的下载绝不会替换现有本地文件，也不会确认同步进度。大文件上传保留按大小计算的时间预算；结果不明确时由正常的同步恢复流程处理，而不会盲目重新发送。

## 扩展现有账户

直接为应承载它们的账户添加文件、日历或邮箱。对 Google 和 Microsoft 来说，这是一次授权，涵盖该账户已有的全部内容以及新增的服务。

打开**云账户**，选择现有账户，把缺少的服务开启（手机上：点击**添加**）。现有服务保持连接，某项服务失败也不会拖累其他服务。当此设备的登录方式允许邮件时，Gmail 会并入 Google 登录；否则 Plainva 会在同一个账户上要求输入应用专用密码。取消助手不会断开已完成的连接。移动文件迁移保留源库，优先考虑匹配的现有目标库，否则准备独立容器。同名冲突文件会逐一比较，并保留双方内容。加密目标通过现有配对流程打开。

在移动端添加文件时，Plainva 会在迁移前显示来源、目标及同名冲突。现有内容和服务得以保留，中断的迁移可以重试。

## 自托管服务器的证书

Android 也信任你在系统设置中安装的证书颁发机构。此设置适用于所有使用 Android 平台配置的 Plainva 连接，并非仅限某个 WebDAV 服务器。桌面 HTTP 连接使用系统证书颁发机构及公共根证书；iOS 使用系统信任设置。仍会验证有效期和服务器名称。过期、尚未生效或属于其他服务器的证书必须在服务器或地址配置中修正。Plainva 不提供接受所有证书的选项。如果系统未说明确切原因，Plainva 只报告验证失败，不猜测原因。移动端原生 HTTP 诊断仅记录方法和错误代码，不包含凭据、证书名称或私有服务器路径。
